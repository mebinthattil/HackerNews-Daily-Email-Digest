F/OSS Comics #13: BSD Unix, Part 3 – The Beginning of BSD Unix

134 points • by joonehur • 8 comments
Summary

Berkeley’s BSD began in 1977 when Bill Joy packaged a Pascal compiler and the ex editor as a supplemental tape for existing AT&T Unix systems; distribution required only a tape and postage for holders of a Unix source license. The first release (1BSD) was a collection of tools, not a standalone OS, and about 30 copies were shipped. Joy expanded the bundle with vi, the C shell, and other utilities for the second release (2BSD), shipping roughly 75 tapes and handling requests personally. With the arrival of a VAX at Berkeley in 1978, graduate student Ozalp Babaoglu added virtual‑memory support to Bell Labs’ 32/V Unix; Joy and collaborators integrated and debugged this kernel, enabling larger address spaces for applications like the Macsyma algebra system. Porting of ex, vi, the C shell, and the Pascal system to the VAX produced 3BSD, released in December 1979. Its successful deployment on the VAX attracted DARPA/ARPANET attention, highlighting Unix’s portability across heterogeneous research machines.

Show HN: I've updated my Linux System Call website and API

25 points • by guitmz • 1 comments
Summary

Linux syscall.sh aggregates complete syscall tables for 27 architectures, covering kernel versions 3.3 through 7.3. Each architecture has a JSON file (e.g., /x64/syscalls.json) that lists every syscall number, argument registers (ARG0–ARG5), return register, and the exact entry instruction (int 0x80, syscall, ecall, svc, etc.). The JSON records the kernel release when a syscall first appeared (since) and, if applicable, when it was removed (removed_in); a “all, with removed” view marks dropped syscalls with their removal release. Data are generated directly from kernel source by parsing SYSCALL_DEFINE macros across all mainline releases, ensuring the numbers match the kernel dispatcher. Short descriptions are taken from the Linux man‑pages project, with additional io_uring details from liburing. An API (e.g., https://api.syscall.sh/v2/syscalls/x64/read) provides programmatic access to the tables, diffs between releases, and full history. The site rebuilds automatically whenever the underlying syscall data changes.

Mystery of 60-Second Fluctuations in Power Grids Solved

142 points • by _Microft • 11 comments
Summary

Large‑scale battery storage systems periodically verify their state of charge, typically initiating a power‑check at the start of each minute. Measurements on the Jülich “Living Lab Energy Campus” at 80 points showed synchronized spikes in electricity consumption precisely at these one‑minute intervals, matching the 60‑second frequency dips observed by Tennet Germany and other operators. The researchers conclude that the collective, clock‑driven checks of many batteries produce a global one‑minute disturbance in grid demand, which can cause brief turbine slow‑downs and increased wear, as seen in hydro‑electric plants and in Ireland where battery‑driven data centres amplified the signal four‑fold between 2016 and 2021. While batteries are the primary source, other digitally controlled loads (e.g., HVAC, heat pumps, appliances) may contribute similar patterns. Randomising the timing of these checks would mitigate synchronization effects. Findings are detailed in Nature Energy (2026), DOI 10.1038/s41560‑026‑02144‑0.
