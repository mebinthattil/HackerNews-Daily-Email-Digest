Court agrees with EFF: Utah's VPN law demands a technical impossibility

622 points • by hn_acker • 18 comments
Summary

Utah’s SB 73, enacted to regulate adult websites, requires platforms to block VPN users or accurately determine each visitor’s physical location to enforce age‑verification gates. The statute also bans sites from providing VPN usage instructions, making Utah the first state to target VPN circumvention of age checks. A federal judge issued a preliminary injunction blocking the law’s VPN provisions, finding that it likely violates the Constitution by imposing an unreasonable burden on businesses nationwide and demanding perfect geolocation—a capability that does not exist. The court noted that compliance would force entities such as Aylo (owner of Pornhub) to verify the age of all 28 million users worldwide, or block all VPN traffic, both impractical and overly intrusive. Proposed administrative rules calling for “commercially reasonable geolocation obfuscation detection systems” rely on unreliable heuristics (e.g., latency, time zones) and would expand surveillance. The injunction halts enforcement pending further litigation, setting a precedent against state mandates that require technically impossible or overly invasive tracking of internet users.

The Forgetful CPU (Linux on M4)

209 points • by signa11 • 7 comments
Summary

The post details the author’s effort to boot Linux on an M4‑based Mac mini. M4 introduces Secure Page Table Monitor (SPTM), which prevents the MMIO tracing used for earlier Apple‑Silicon bring‑up and forces changes to the m1n1 hypervisor. Initial attempts failed because GXF and the Reset Vector Base Address Register (RVBAR) writes caused crashes; skipping these writes allowed m1n1 to run in BRINGUP mode. Early‑boot output was obtained by inserting a minimal debug_putc routine, revealing that Linux’s MMU setup lacked a 1:1 mapping for the UART MMIO region, which was added to the initial page tables. A write to the CPU register SYS_IMP_APL_VM_TMR_FIQ_ENA_EL2 also caused a crash until newer iBoot versions unlocked it. The secondary‑core startup required an smp_start_offset; after applying it, the system still crashed due to a broken WFI implementation. Replacing all WFI/WFIT instructions with NOPs enabled multi‑core boot, and a kernel boot‑argument now disables the faulty WFI path. The fix has been merged into mainline Linux and m1n1, allowing M4 (and later M4 Pro/Max, M5) devices to boot Linux with all cores active.

Cloudflare OHTTP gateway

68 points • by est • 11 comments
Summary

Cloudflare announced the closed‑beta launch of its OHTTP Gateway, a managed service that decapsulates Oblivious HTTP (OHTTP) traffic and returns encrypted responses, enabling developers to receive HTTP requests without exposing client IPs or TLS fingerprints. The OHTTP architecture separates a relay (which forwards encrypted requests while stripping client identifiers) from a gateway (which performs the HPKE decryption/encryption), creating a “double‑blind” privacy model where no single party sees both identifiers and content.

Key points:
- Two product options: Cloudflare OHTTP Relay (self‑hosted gateway) for off‑Cloudflare servers, and Cloudflare OHTTP Gateway (managed) for apps already behind Cloudflare’s CDN/Workers or for third‑party relays.
- The Gateway runs on Cloudflare’s global anycast edge network, minimizing latency and handling automatic scaling, key management, and relay authentication via Cloudflare Access.
- It supports standard and chunked OHTTP, isolates non‑OHTTP traffic, and enforces separation of trust by refusing requests from Cloudflare Workers or proxied hosts.
- Ideal for privacy‑focused apps (e.g., Flo Health Anonymous Mode, Apple Private Cloud Compute) that need to hide user identifiers while keeping backend performance.

Developers must provide their own relay, implement an OHTTP client, and can test with Cloudflare’s pvcli tool. Registration for the waitlist is required.

Barcodes are about to go extinct

30 points • by rmason • 13 comments
Summary

QR codes, a 2‑D barcode invented by Masahiro Hara at Denso in the early 1990s, are poised to replace the 1‑D Universal Product Code (UPC) that has dominated retail for five decades. The UPC’s network effect, enforced by GS1’s company‑prefix licensing, created a de‑facto monopoly; however, GS1 announced a shift to QR codes (dubbed “Sunrise 2027”) to address limitations of traditional barcodes, especially for detailed traceability in food recalls and regulatory compliance. QR codes can store up to 200× more data, enabling links to origin, ingredients, allergens, expiry, sustainability, and disposal information, while remaining readable at checkout. Early adoption is already evident, with roughly half of surveyed retailers implementing QR capabilities and major brands (e.g., Unilever) re‑packaging tens of thousands of SKUs. Transition challenges include dual‑code packaging, data‑link infrastructure, and system integration; failure to adopt may risk shelf placement as major retailers upgrade scanners. Consumer preference for QR‑linked information is high (≈79 %).
