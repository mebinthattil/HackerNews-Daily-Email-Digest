Astra can read and write weights to improve Qwen

2693 points • by dbreunig • 286 comments
Summary

Weight‑Space Programming is demonstrated by a frontier LLM (referred to as Astra/GPT‑6 Astracan) that directly reads and writes neural‑network weights using natural‑language prompts, without gradient‑based training. Across eight experiments:

1‑3. Astra infers network behavior from raw weight tensors alone—identifying the game a PPO policy was trained on, the shape generated by a DDPM diffusion model, and the training language of a 7.2 M‑parameter character transformer, even when only middle layers are provided.
4. Given a PPO car‑control policy that stalls on a ramp, Astra edits 3.5 % of its 171 k weights, enabling 100 % success across 1 024 episodes.
5. Astra synthesizes weights from scratch for three MinAtar games; the resulting agents surpass PPO trained for 100 M steps and approach PPO trained for 500 M steps.
6. Scaling to a 1.5 M‑parameter Go network, Astra writes functional weights with zero forward passes and improves performance with up to 50 passes.
7. Using attention‑pattern analysis, Astra distinguishes a sycophantic from an honest Gemma‑3 270 M model.
8. Editing 0.016 % of Qwen‑3.5‑0.8 B’s weights removes looping behavior, raising MATH‑500 accuracy from 7.9 % to 48.1 % and tripling IFEval scores.

These results show that LLMs can natively interpret, repair, and generate neural‑network weights, suggesting a new paradigm for model auditing, rapid optimization, and capability steering.

81 points • by campervans • 10 comments
Summary

It generates enterprise ontologies, reconciles definitions across systems, and provides certified query validation with provenance. Key features include:

  • Discovery & grounding: builds AI‑ready knowledge graphs, connects to existing ontologies, and assigns trusted business meanings to metrics, entities, and relationships.
  • Validation & exposure: checks generated SQL queries against certified definitions and serves context via MCP, CLI, and REST API.
  • Deployment: available as Docker‑Compose (local) or Helm chart for Kubernetes; stores catalog metadata in PostgreSQL and uses NVIDIA NIM endpoints for LLM, embedding, and reranking models (default models configurable via environment variables).
  • Security: supports Better Auth RBAC, optional Vault integration for encrypted DB credentials, SSO, and API tokens (SHA‑256 hashed, role‑based, revocable).
  • Licensing: Apache 2.0; third‑party components listed in THIRD_PARTY_NOTICES.md; external contributions are not accepted.

The repository includes docs for text‑to‑SQL benchmarking, MCP server usage, and agent skill packages.

  • Media support: CD (export WAV + CUE or RAW tracks, 0D/AA 2‑level grayscale); DVD (ISO export, A5/92 grayscale); BD‑R (ISO/UDF 2.01, pure graphics or file system, MMC sequential write).

  • Architecture: modular via IOpticalDiscModule; source split into Core, Imaging, Burning, format‑specific modules, tests, and packaging scripts.

Efficient algorithms, the Exponential Time Hypothesis, and losing the plot

61 points • by sebg • 11 comments
Summary

The post traces the historical difficulty of rigorously defining algorithmic efficiency. It cites Jack Edmonds’s 1965 work on maximum‑matching, where “good” algorithms were described only informally and later quantified by a running‑time bound expressed as a function of input size (vertices + edges). Edmonds warned against rigid criteria that might stifle practical advances, yet his own blossom algorithm was labeled “quartic,” prompting later researchers to adopt polynomial time as the standard notion of efficiency while treating exponential time as inefficient. The author argues that polynomial bounds can still be impractically large (e.g., (n^{1000})) and that asymptotic reasoning encourages “galactic algorithms” with unrealizable runtimes. This critique is applied to a recent claim by OpenAI of a sub‑exponential SAT algorithm, whose stated bound holds only beyond astronomically large instance sizes (far exceeding the number of atoms in the universe), effectively reducing to exhaustive search for any feasible problem. The post concludes that such results illustrate the persistent inadequacy of current efficiency definitions.

If you love a website, back it up

563 points • by ingve • 67 comments
Summary

The author recounts losing a long‑standing personal site (teapuppies.com) and urges individuals to preserve web content themselves. Personal web archiving can be done with readily available tools that output standard WARC/WACZ files:

  • ArchiveWeb.page browser extension (Chrome): install, start/stop archiving while browsing; captures single pages, whole sites, or social‑media profiles and provides a dashboard for preview.
  • ArchiveWeb.page standalone app: same functionality with its own browser, convenient for local archive review.
  • Browsertrix: an automated web‑crawler web app (free trial, then paid per use) that crawls entire domains or scoped sections; open‑source version can be self‑hosted.

Archived content can be replayed locally or shared via the open‑source ReplayWeb.page viewer, which can be embedded on any site with a simple JavaScript snippet. Since archives are single WACZ files, multiple copies can be distributed to ensure preservation. The tools mentioned are mostly free, with Browsertrix being the only paid option after the trial.
