Qwenputer: A functioning, deterministic RISC-V CPU inside Qwen3.5

471 points • by csmantle • 55 comments
Summary

Qwenputer embeds a deterministic 32‑bit RISC‑V core (RV32IM + Zba, with a small bignum unit) inside the weights of a stock Qwen 3.5 4B model. By fixing the Gated DeltaNet (GDN) attention heads to gate = 1, write‑strength β = 1 and using one‑hot key encoding, each GDN head stores exact, addressable rows that function as RAM. A compiler translates CPU micro‑operations into transformer‑layer components (attention heads for look‑ups, feed‑forward units for arithmetic, GDN heads for memory), so the CPU runs during the model’s forward pass without external tooling. The added CPU occupies 11 extra layers, passes the official riscv‑tests, and has executed >18 M instructions error‑free, handling C and MicroPython code albeit slowly.

Benchmarks show Qwenputer reaching 97.5‑100 % accuracy on DeepMind arithmetic suites and 100 % on NUPA long‑integer tasks, matching or exceeding a Python‑tool baseline. An experimental in‑model filesystem stores up to 512 files (≈53 k tokens) in 1 024 hashed slots, persisting across conversations.

Limitations include a doubled checkpoint size (~18.8 GB), reliance on the RvChat driver to load firmware, and slower throughput (~3.2 k CPU tokens s⁻¹ on an L4 GPU). The model and code are released on Hugging Face/ModelScope and GitHub, with future work aimed at native MicroPython execution and speed improvements.

Zero click, silent, remote Android DoS

66 points • by MarkBlah • 13 comments
Summary

The report details a zero‑click denial‑of‑service vulnerability in Android’s telephony stack (WapPushOverSms.decodeWapPdu). An incoming WAP‑Push SMS on port 2948 contains a 5‑byte uintvar that decodes to 0x80000000; the value is cast to a signed int without bounds checking and used as an array size, triggering an uncaught NegativeArraySizeException on the main telephony thread. The crash terminates com.android.phone, dropping active voice calls—including emergency calls—and causing a 1‑2 second service outage while the process restarts. Repeated delivery (≈30 messages) races with SQLite writes, corrupting the SMS store so the phone crashes on every boot, effectively bricking the device. Recovery requires removing the SIM, acknowledging pending messages on a non‑Android handset, and cleaning the database via ADB; a factory reset alone is insufficient. The bug reproduces on multiple models (Pixel 9, Samsung A‑series). Google classified it as a non‑security issue and refused a fix; the suggested mitigation is a simple range check before the cast. The vulnerability can cause carriers, under Australian regulations, to block devices that cannot reach emergency services.

Flash layout maps page tables, kernel, and compressed ZLIB sections to specific addresses; no Linux filesystem image was found.

Access is gained by logging in with the admin password, pressing Enter for username, then issuing SET USER 640184.571119 to enter debug mode. Forging a Microsoft Edge Full Chain with Logic Bugs Only

Summary

A logic‑only Microsoft Edge exploit chain for Pwn2Own 2026 combines five independent bugs with two Windows features to achieve arbitrary code execution (ACE) without memory corruption.

  • EdgeCAGuidanceNavigationThrottle fires only from Microsoft origins; the throttle lacks a cross‑window opener check, allowing a malicious site to open a new window (bypassing the origin test) and trigger the throttle.
  • A hard‑coded popup‑blocker whitelist lets the attacker open the required window despite modern popup restrictions.
  • The OneAuth feature automatically creates and signs‑in a user profile when visiting Microsoft sites, guaranteeing a signed‑in Edge instance.
  • A CORS misconfiguration on assets.msn.com enables an authenticated fetch that leaks the victim’s email address, satisfying the throttle’s email match.

The throttle then initiates a browser‑process navigation with a null source_contents, causing a sourceless navigation UXSS that runs JavaScript in any origin, ignoring CSP.

Using the privileged read:// (Immersive Reader) WebUI, the attacker calls chrome.edgeFeedbackPrivate.zipDiagnosticLogFiles to write arbitrary files, overwriting protocols.json to permit any origin to launch arbitrary protocol handlers. By setting the handler to telnet:// and placing a malicious executable in a writable PATH directory, the chain gains ACE. A new faster algorithm to compute 64-bit signed floor division

64 points • by benjoffe • 3 comments
Summary

Signed 64‑bit floor division by a compile‑time constant can be implemented far faster than the naïve x/ d or x% d approach. The article surveys existing techniques—mul‑shift with a sign‑bit correction, “uncooperative” divisor handling, the XOR‑trick for positive divisors, and Robison’s multiply‑add‑shift formula—and shows their typical cost of ≈ 1 multiplication + 2–3 cycles plus extra branch or correction instructions. Using Granlund‑Montgomery’s invariant‑integer method a branchless template generates a single mul‑shift (or mul‑add‑shift) that yields correct floor results for any signed non‑zero divisor known at compile time. Benchmarks on ARM and x86‑64 report 5‑20 % higher throughput for the majority of 64‑bit divisors, with comparable or better latency; negative divisors are handled by a symmetric case. The implementation compiles to a mul‑high (or fused multiply‑accumulate) and a final shift, avoiding runtime modulo or branching, and works across bit‑widths, including 32‑bit and SIMD contexts.
