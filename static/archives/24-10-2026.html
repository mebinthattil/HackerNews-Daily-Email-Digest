Twelve years of distributed SQLite

173 points • by otoolep • 14 comments
Summary

The article traces the evolution of “distributed SQLite” from the 2014 launch of rqlite, the first open‑source system to pair Raft consensus with SQLite. rqlite, built as a CP system with leader‑only writes and majority acknowledgment, originally used goraft and later HashiCorp’s Raft implementation. Parallel efforts included Expensify’s Bedrock (Paxos‑based) and ActorDB (Raft per actor), but rqlite remained the general‑purpose, standalone offering.

In 2017 Canonical released dqlite, a C‑based library embedding its own Raft, differing mainly in packaging (library vs. server). 2021 Litestream introduced WAL streaming to S3 for single‑node disaster recovery, addressing a different use case (machine failure without clustering). Subsequent extensions explored other design corners: cr‑sqlite added CRDTs for AP behavior; libSQL (forked by Turso/Supabase) modified the SQLite engine for edge‑replicated services; SQLite Cloud provided hosted Raft replication.

From 2022 onward, platforms such as Cloudflare D1 and Turso offered managed, serverless SQLite instances. The author concludes that three design spaces—consensus (CP), streaming (single‑writer recovery), and merge (AP/CRDT)—have emerged, with open‑source projects persisting while commercial services capture the majority of funding.

Bringing uv and ty together

134 points • by Ravencentric • 12 comments
Summary

The Astral team released an experimental integration of uv (package manager) and ty (type checker/language server). The integration enables:

  • First‑class script support: Using PEP 723 inline metadata, uv creates an isolated environment for each script, and ty uses that environment for type checking, completions, hover, and “go to definition”. Scripts in the same repository may have differing dependency and Python version requirements.
  • Unified diagnostic command: uv check automatically prepares the project’s environment, installs dependencies, and runs ty. It works on individual packages (uv check --package <name>), all packages (--all-packages), or a single script (--script <file>). The ty version is taken from the lockfile, ensuring reproducible CI and pre‑commit hook behavior.
  • Implementation details: The integration leverages uv workspace metadata to supply ty with package, dependency, and interpreter information. Automatic environment setup for PEP 723 scripts is opt‑in. Required versions are uv ≥ 0.12.3 and ty ≥ 0.0.76.
  • Future direction: Plans include extending uv check to incorporate Ruff linting and adding checks that combine dependency data with type information (e.g., unused‑dependency detection). The feature is currently experimental and feedback‑driven.
