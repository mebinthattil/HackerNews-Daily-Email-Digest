Livenerf: Has Opus 5.5 been nerfed yet?

616 points • by bryan0 • 44 comments
Summary

livenerf is an append‑only, deterministic benchmark designed to detect capability drift in a single model after release. Using Claude Opus 5.5 (launched 2026‑09‑22) as a case study, the suite runs daily for 30 days, with the first 10 days forming a baseline and two subsequent 10‑day windows for drift detection. A calibrated panel of 78 “sometimes‑right” items—drawn from GPQA Diamond, MMLU‑Pro, competition‑math and AIME 2025‑26—provides the primary metric; paired per‑item accuracy differences are computed with clustered standard errors, requiring a 99 % interval excluding zero in both windows, a minimum 3‑point change, and no concurrent shift in a control arm (Claude Opus 5). Secondary signals include output‑token counts, which reveal effort reductions before accuracy changes. The framework relies on Inspect (UK AI Security Institute), uses frozen prompts, a pinned Claude‑Code CLI, and pure‑function graders; all logs are immutable. Validation shows the system can detect ≈7.5‑point accuracy shifts over a 10‑day window, while same‑family model swaps of ~4 % token reduction remain undetectable. The repository contains full design, calibration, validation documents, and scripts for automated daily execution.

The article describes a systematic approach to verify that Rust structs and WGSL shader structs share identical memory layouts for WebGPU compute shaders. A mismatch is demonstrated with a mat3x3f matrix: WGSL pads each row to 16 bytes (total 48 bytes) while Rust’s [[f32;3];3] occupies only 36 bytes, causing incorrect offsets (e.g., image_size shifted from 36 to 48). The author uses Naga to parse WGSL, extract struct members, and compare their offsets and sizes against Rust equivalents. To automate this, the Facet library provides runtime reflection via #[derive(facet::Facet)], exposing a SHAPE type with field names, offsets, and sizes. A generic compare_struct_layout<T: facet::Facet> function parses the shader, validates overall struct size (handling trailing dynamic arrays), checks each field’s offset and size, and ensures all WGSL fields appear in the Rust struct. Unit tests instantiate this checker for each configuration struct (e.g., ColorConfig, MergeConfig), guaranteeing layout correctness without manual offsets.
