18 points • by hsfzxjy • 2 comments
Summary

npunlock is a Windows‑only toolchain that enables custom C kernels to run on Intel Core Ultra NPUs (Meteor Lake / NPU3720). It bridges the gap between user‑written C code and Intel’s ACT‑SHAVE processors, allowing these kernels to be embedded in standard NPU graphs compiled with Intel’s driver. The project supplies header files (e.g., npunlock/npu3720_kernel.h) and uses the MoviTools MVC_DEPEND toolchain for compilation; the required binaries (npunlock.dll, npunlock_worker.exe) are packaged with the Python module. Example code demonstrates a full‑precision (FP32) GELU implementation, comparing NPU output against NumPy and reporting maximum absolute error. Supported features include static‑shape FP16 unary and binary kernels, mixed‑precision graphs with independent FP32‑unary and FP16‑binary branches, and reusable NumPy‑compatible buffers via Python, CLI, or native C APIs. Limitations: Windows x64, Meteor Lake/NPU3720, static shapes, known tensor layouts, and no OpenVINO runtime required. Linux ports and newer NPU generations are untested but encouraged for community contributions.

ReBarUEFI: Resizable BAR for almost any UEFI system

143 points • by nateb2022 • 8 comments
Summary

A UEFI DXE driver enables Resizable BAR (RBR) on systems lacking native support, improving GPU performance and required for optimal Intel Arc operation. The driver replaces the PreprocessController function of the PciHostBridgeResourceAllocationProtocol, reading a Resizable BAR size from the ReBarState NVRAM variable and applying it during PCI enumeration. Optional steps include enabling 4 GB decoding, disabling CSM, and applying BIOS patches for large BAR handling. The project provides scripts (buildffs.py, CMake‑based ReBarState) for building the driver on Windows or Linux, as well as UEFIPatch patches to lift 4 GB, 16 GB, and 64 GB BAR limits, prevent 64‑bit BAR downgrades, and expand MMIO space up to 512 GB on modern chipsets. Compatibility notes: it can work on PCIe Gen2 (e.g., i5‑2500K), Linux can resize BARs with 4 GB decoding or via DSDT patches and the kernel pci=realloc option; Windows requires BIOS modification. Unsupported BAR sizes may prevent boot, resolvable by clearing CMOS. Performance gains of up to ~12 % FPS were observed with a 2 GB BAR on an i5‑3470 + RX 580 system.
