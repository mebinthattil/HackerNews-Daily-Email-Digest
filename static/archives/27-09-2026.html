Flip Fluid on Flip Dots

67 points • by blutack • 5 comments
Summary

A FLIP fluid simulation was implemented on a 13×28 electromechanical flip‑dot panel for the EMF2026 installation. The author acquired surplus Hanover panels (2007) from “Look Mum No Computer”, noting the board overhang prevents seamless tiling and the original driver updates the whole matrix in ~1 s. Each dot flips in ~60 ms with a ≤1 ms polarity pulse; columns can be driven in two passes (high then low) to potentially achieve ~56 ms refresh if pulses are ~1 ms. High current (~0.7 A at 12 V, up to >1 A for faster pulses) and simultaneous coil activation present power and thermal challenges. Desoldering dots proved impractical, so the solution uses inexpensive motor‑driver H‑bridge ICs (MX6208/BE6208/LK6208, SOIC‑8, 0.5 A continuous) mounted on a custom board that replaces column traces. Each 8‑bit shift register (74 595) drives four dots directly; by tying one H‑bridge input high, a single‑ended operation yields push‑pull output without extra diodes. Capacitor‑coupled half‑bridge alternatives were explored but rejected due to size, cost, and quiescent current of BJTs. The final PCB design incorporates 15.24 mm pitch flip‑dot footprints, keep‑outs for test pads, and uses KiCad despite its limited repetitive‑component workflow.

C's Flexible Integer Sizes Were Not a Design Mistake

23 points • by ibobev • 8 comments
Summary

C’s native integer types (char, short, int, long, long long) were intentionally sized to match each machine’s “natural” word, providing minimum guaranteed ranges rather than fixed widths. In the 1970s hardware varied widely—bytes could be 6‑9 bits, word sizes spanned 12‑64 bits, and signed representations included two’s‑complement, ones‑complement, and sign‑magnitude. Fixed‑size types would have forced costly multi‑instruction arithmetic on 16‑bit CPUs, extra masking on 36‑bit machines, and software emulation on non‑two’s‑complement hardware. The C standard codified this philosophy with minimum ranges and, from C99, optional exact‑width types (e.g., int8_t) plus required least/fast types (int_least32_t, int_fast32_t). Projects such as Lua demonstrate portable code that queries ranges (e.g., using UINT_MAX) and selects types accordingly, avoiding assumptions about byte size (CHAR_BIT ≥ 8). Modern languages often fix widths because contemporary platforms have converged on 8‑bit bytes and two’s‑complement arithmetic, yet they retain a natural‑size integer (e.g., Rust’s isize, Go’s int). Thus, C’s flexible integer sizes were a deliberate design for portability, not a mistake.
