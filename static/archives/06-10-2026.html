Dust: Pretraining Transformers Without Backpropagation

202 points • by E-Reverance • 22 comments
Summary

Dust introduces a zeroth‑order optimizer for pretraining transformers that perturbs activations (“node perturbation”) independently at each token, treating each token as a member of a virtual population evaluated in a single forward pass. The reward‑weighted perturbations yield an estimated output error whose outer product with the layer input provides a weight gradient, mirroring backpropagation’s update but without differentiability requirements. Compared to weight‑space evolution strategies such as EGGROLL, Dust is 10³–10⁴ times more compute‑efficient from 1 M tokens onward, because activation‑space perturbations avoid materializing full weight copies. Empirical studies on GPT‑style models (8 layers, width 512) pretrained on FineWeb show that Dust matches backpropagation at modest token budgets and surpasses it at larger budgets (10–20 M tokens) when population size is increased, with gradient cosine similarity to backprop improving as population grows. Larger models (e.g., 243 M parameters) demonstrate greater population efficiency than much smaller counterparts, contradicting conventional expectations about over‑parameterization. Dust thus provides a scalable, backprop‑free alternative for transformer pretraining, though further work is needed for compute‑parity with standard training.

Resurrecting iChat Audio and Video Conferencing

53 points • by thepipetogrep • 6 comments
Summary

Add a DNS entry for configuration.apple.com pointing to a reachable SNATMAP server (e.g., 157.230.2.213) on Macs running OS X Leopard or Snow Leopard. iChat AV originally obtains its public IP via an HTTP request to http://configuration.apple.com/configurations/macosx/ichat/1/snatmap.txt, then sends a UDP request to the returned SNATMAP server (port 5678) which replies with the client’s external IP and port. Modern Apple servers no longer respond, causing iChat to exchange private LAN addresses and fail NAT traversal. The author reverse‑engineered the SNATMAP protocol (UDP, 16‑byte request: type 1, nonce, unused local IP/port; 16‑byte response: type 2, same nonce, external IP, external port) and implemented a minimal Python server. By hosting the SNATMAP file on a custom web server and ensuring source‑port‑preserving NAT on routers, iChat can re‑establish peer‑to‑peer RTP audio/video calls, even with non‑Apple webcams. The solution works with typical NAT routers and BSD‑based routers after enabling source‑port preservation.
