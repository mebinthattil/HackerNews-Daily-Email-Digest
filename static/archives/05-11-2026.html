Baidu released ERNIE 5.5 Flash Base

37 points • by pretext • 6 comments
Summary

ERNIE‑5.5‑Flash‑Base is a 280 B‑parameter sparse Mixture‑of‑Experts (MoE) language model with 14 B active parameters per token. It uses 43 Transformer layers (hidden size 4096, 64 heads) and supports up to 128 K training context and 1 M token context for fine‑tuning. Core architectural innovations include: Latent‑Gated Sparse Attention (MLA for full‑token access in 1/7 layers, Heavily Compressed Attention in the rest, low‑rank gated attention, and virtual head attention); Multi‑Router Latent MoE (512 routed experts, top‑10 selection, latent‑space experts, bias‑corrected load balancing); Manifold‑Constrained Hyper‑Connections replacing standard residuals; MultiMax output head with piecewise temperature; and ECHO, which reuses the final backbone layer for multi‑token prediction. The tokenizer is a 200 K BPE with right‑to‑left digit grouping for numbers. Pre‑training consumed 33.5 T tokens using the Muon optimizer (FP8 mixed precision) and a context gradually expanded to 128 K. The corpus emphasized multilingual web data, repository‑scale code, and long‑context documents. Training infrastructure featured a distributed Muon optimizer with communication‑efficient updates and memory‑balanced sharding, plus the FlashMask‑4 attention kernel supporting head dimensions up to 576. Benchmarking shows strong performance, especially on reasoning, code, and long‑context tasks. The model is released on Hugging Face in FP8 and BF16 formats for further fine‑tuning or research.

Lemmings CSS Animation

209 points • by MarkBlah • 28 comments
Summary

The Walker Playground demonstrates a dynamic text‑based navigation environment where each line of reflowing text functions as a separate “floor.” As the browser window is resized, columns adjust, allowing walkers to move vertically from one line to the next, drop off short line ends, and land on the underlying element. Because line spacing is set tighter than a walker’s height, textual content never obstructs movement; only UI elements such as borders, boxes, buttons, images, and input fields act as barriers. This design prevents walkers from becoming trapped between adjacent lines. Additionally, a continuous long floor positioned near the page bottom serves as a catch‑all surface for any walkers that descend past all other elements. The system thus provides a clear, obstruction‑aware model for testing resize behavior and element interaction.

Summary
  • Zig now enforces explicit parentheses for ambiguous operator combinations (e.g., x orelse y == z). The compiler reports “ambiguous operator precedence” errors and requires disambiguation, while common arithmetic expressions retain their previous precedence.
  • A precedence table for unambiguous operators (*/%, +‑, comparison, logical) remains unchanged; any other mixes will be parenthesized automatically by zig fmt --upgrade (flag to be removed after one release). Manual fixes are recommended to catch potential bugs.
  • Naked packages (without build.zig.zon) can now include optional version and paths fields; the dependency name participates in the hash only when a version is provided, reducing hash brittleness and allowing controlled updates.
  • New CLI options: --print-tree displays dependency trees with hashes; --configure exits after configuration (replacing old --fetch behavior); --fetch now fetches all dependencies without configuration.
  • std.ArrayList gains pointer‑stability locks (lockPointers/unlockPointers) to prevent dangling pointers when the underlying buffer reallocates. A demonstrated bug shows how storing slices from a growing ArrayList can corrupt data; applying the locks triggers an assertion when stability is violated.
