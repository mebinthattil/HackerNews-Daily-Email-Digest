The baffling intelligence of a single cell (2024)

303 points • by jsomers • 18 comments
Summary

E. coli chemotaxis relies on a sensory‑motor circuit that translates extracellular ligand levels into directed swimming. Attractant molecules bind specific transmembrane chemoreceptors (e.g., the aspartate receptor), causing conformational changes that inhibit the associated CheA kinase. Reduced CheA activity lowers the phosphorylation rate of the response regulator CheY; less CheY‑P binds the flagellar motor’s C‑ring, decreasing motor reversals and thus tumbling. In uniform conditions, runs (≈1 s) alternate with brief tumbles, producing a biased random walk. Adaptation is achieved by reversible methylation of receptor “struts”: attractant binding opens methyl‑acceptor pockets, allowing CheR to add methyl groups, which stiffen the receptor and diminish its signaling output, while CheB removes methyl groups when signaling declines. This feedback grants sensitivity over five orders of magnitude and memory of concentration changes on the order of seconds. The network includes parallel phosphorylation/dephosphorylation cycles (CheA/CheY, CheZ), providing rapid, ATP‑driven amplification and tunable signal processing analogous to a biochemical computer.

Summary

The article describes building a commercial web product (marketyour.games) in 2026 using a minimalist C‑CGI stack. The environment consists of OpenBSD, a statically linked C binary, httpd, and SQLite; no framework, templating engine, or separate database server is used. The CGI program reads HTTP environment variables, generates HTML directly, and accesses a SQLite database via its C API. Outbound services (Stripe, Postmark) are handled with libcurl; libsodium provides cryptographic functions, and libcjson parses JSON. Only libcurl and libsodium are external build dependencies; libcjson and SQLite are vendored as single‑file sources. The author cites benefits: simplicity, low supply‑chain risk, ease of debugging, minimal tooling (Vim, Make, standard C utilities), and reduced operational overhead compared to traditional stacks with separate web and application servers. Drawbacks include the need to implement common utilities (cookie handling, query parsing, escaping) manually. The author concludes that CGI’s perceived obsolescence is unfounded today, with process forking inexpensive and FastCGI available if needed.

Who is vfmaddrnd231pd?

214 points • by pngmangi • 6 comments
Summary

vfmaddrnd231pd is documented in older Intel Software Development Manuals (e.g., 2024 edition) as a fused‑multiply‑add of packed double‑precision values with per‑instruction rounding control, using an immediate byte to select rounding mode, denorm‑zero (DAZ), flush‑to‑zero (FTZ), and exception suppression. The entry lists a VEX‑encoded opcode (VEX.DDS.128.66.0F3A.W1 B8 /r /ib) and mentions intrinsics _mm_fmaddround_pd and _mm256_fmaddround_pd. In practice, no assembler (GNU as, clang, ICC) recognizes the mnemonic, and execution on a Haswell CPU triggers an undefined‑instruction exception (#UD). The “DDS” field appears only in this entry and was removed from later manuals, suggesting documentation inconsistency. The instruction is absent from the 2026 SDM edition, indicating it may have been planned but subsequently dropped before silicon implementation. The author concludes the entry is likely an editorial artifact rather than a functional ISA feature.
