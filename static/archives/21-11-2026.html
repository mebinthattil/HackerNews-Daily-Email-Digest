Inkling 2 Mini

1047 points • by jasondavies • 63 comments
Summary

Inkling 2 Mini is a 26.4 B‑parameter Mixture‑of‑Experts transformer (3.4 B active, 5.4 B weight activations per token) that loops its middle 12 layers three times per token, enabling deeper reasoning without expanding the parameter count. It achieves state‑of‑the‑art results among open‑weight models < 100 B parameters, e.g., 48.2 % on DeepSWE v1.1, 46.5 % on Vals Index v2.2, and top scores on SWE‑bench Pro v2. The model runs in ~20 GB memory (NVFP4 precision for 20 layers, MXFP8 for the final four) and can execute on consumer laptops. Training involved 48 % sparsity, two‑thirds expert pruning, a 1 T‑token distillation phase, followed by SFT and 2.2 T‑token RL, preserving performance after pruning. Looping improves no‑CoT time horizon (16 s → 37 s up to three passes) and boosts multi‑hop reasoning, while factual recall remains comparable to models of similar size. Monitorability tests show shorter, legible CoT with more loops and minimal loss of controllability. Limitations include weaker multi‑turn chat and complex‑constraint instruction performance. Weights and a variable‑loop variant are released open‑source on Tinker and Hugging Face, with inference support via Ollama, vLLM, Unsloth, etc.

ClawDOS – An AI coding agent for DOS

78 points • by Ricapar • 7 comments
Summary

ClawDOS is an AI‑driven coding assistant that runs natively on an IBM PC XT (8088, 4.77 MHz, 640 KB RAM, CGA). The core program, HARNESS.EXE (176 KB), implements the Claude Messages API, issuing requests, parsing streamed JSON replies, and invoking a suite of 18 DOS‑based tools (file I/O, search, compile, run, memory access, port I/O, audio, text‑art, etc.). Because the 8088 cannot perform TLS, a separate “bridge” PC runs a TLS tunnel (Python 3, socat/stunnel) that forwards plain‑HTTP from mTCP to the Claude API over HTTPS.

Key capabilities demonstrated include: - Generating, compiling (Turbo C 2.0) and executing source files (e.g., PRIMES.C) entirely on‑device. - Persisting “memories” and chat transcripts on disk, enabling continuation after power loss. - Capturing CGA video memory via timer‑interrupt hook, encoding a 320×200, 4‑colour PNG, and returning it to Claude. - Interactive UI with scrolling transcript, command shortcuts (/model, /chats, /memories, /new, /quit) and safe‑mode confirmations for file/port changes.

Installation requires a host PC with Python 3, an Anthropic API key, and scripts to fetch FreeDOS, mTCP, Turbo C, and build a bootable CLawDOS.IMG for deployment on a PicoMEM‑based SD card. The software is GPL‑v3 (with bundled GPL‑v2 components).

RCE in Gnupg

26 points • by gdgghhhhh • 3 comments
Summary

GnuPG announces GPGME version 2.3.1, fixing a critical double‑free vulnerability (CVE‑2026‑129975, internal ID T8557) present in all earlier releases. The bug is triggered by an OpenPGP key with an excessively long user ID; the status‑line and key‑listing functions allocate a 1024‑byte buffer, reallocate it as needed, but only update the context pointer after successful completion. Early return paths leave the context pointing to freed memory, causing a second free when the context is released. Exploitation may allow data exfiltration and potentially remote code execution. Affected software includes any product linked against GPGME < 2.3.0, such as Gpg4win, GnuPG Desktop/VS‑Desktop, mail and XMPP clients, Samba, and Flatpak packages. Users should upgrade to GPGME 2.3.1 (or apply the provided patch) and rebuild statically linked binaries against the new library. No changes are required for GPGMEPP or GPGMEQT. New constants (GPGME_PK_MLKEM, GPGME_PK_MLDSA, GPGME_PK_DLTHM) were added in this release.

Clojure will affect the way you think about programming (2017)

107 points • by sammatilda • 15 comments
Summary

Clojure, a modern Lisp introduced in 2007, blends functional programming with pragmatic design. It is a dynamic language with optional typing, emphasizing immutable persistent data structures (lists, vectors, maps) and higher‑order functions. Uniform Lisp syntax enables powerful macros, allowing code‑as‑data transformations and facilitating constructs such as core.async’s CSP‑style channels. Development is REPL‑driven, supporting incremental testing.

The language provides a pervasive sequence abstraction and lazy evaluation, enabling concise, SQL‑like data pipelines using built‑in functions, reducers, and transducers. Clojure.spec offers optional runtime type validation for nested structures, while core.typed adds static typing options.

Object‑orientation is expressed through protocols and multiple dispatch, avoiding deep inheritance hierarchies. Concurrency is native: immutable structures simplify multithreading; mutable references (atoms, refs, STM) handle controlled state changes; futures, promises, and core.async supply asynchronous primitives. Seamless Java interop leverages the JVM ecosystem, and ClojureScript extends these capabilities to the browser. Clojure is employed in production across several companies, making it a practical language for expanding programming perspectives.
