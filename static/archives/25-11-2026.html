Windows Loudness Equalization, reverse-engineered and ported to PipeWire

91 points • by ThrowNotAway • 15 comments
Summary

The repository implements Windows‑style Loudness Equalization for PipeWire by reverse‑engineering WMALFXGFXDSP.dll. It provides two PipeWire modules: modules/loudness inserts a DSP plugin into each application’s playback stream (pre‑volume, pre‑mix) to apply broadband AGC, and modules/limiter adds a look‑ahead limiter on every render device, mirroring AudioEng.dll’s output limiter. An optional GTK3 UI (app/) lets users enable/disable the effect globally or per‑application and set the release time.

Build requires PipeWire ≥ 1.4 and GTK 3; make -C modules/loudness, make -C modules/limiter, and make -C app install the components, with make uninstall for removal. Settings are stored in PipeWire metadata and can be scripted via pw-metadata; defaults live in /usr/share/pipewire/pipewire.conf.d/60-loudness-eq.conf and are overridden by user files in ~/.config/pipewire/. Runtime changes persist in ~/.local/state/pw-loudness-eq/state.conf.

The AGC uses a 50 % overlapped FFT (≈512 samples at 44.1 kHz), 25 logarithmic frequency bands, and computes loudness L = 1.72·Σmax(E_b − T_b, 1e‑32)^0.25. Target gain = min((1300/L)^1.6, 10) (≤ +20 dB) with adaptive attack/release based on a configurable release parameter. The limiter delays by L frames (64 at 44.1/48 kHz), reduces gain when peaks exceed 0.985, and recovers at ~19 dB/s. The modules ignore JACK clients, streams > 8 channels, and Flatpak apps using PipeWire directly. An offline test tool (leq-wav) is included.

SSH Is the Most Underrated Platform in Tech

9 points • by speckx • 1 comments
Summary

SSH is a versatile platform, not just a login tool. It supports tunneling (local, remote, dynamic), file transfer (scp, sftp), key management, port forwarding, jump hosts (ProxyJump), agent forwarding, multiplexed connections, and certificate‑based authentication. Developers often use only basic login, overlooking features that can replace VPNs, custom tooling, and managed file‑transfer products. A properly configured ~/.ssh/config file can simplify host aliases, per‑host options, and wildcard rules, enabling one‑line commands for complex access patterns. Multiplexing (ControlMaster/ControlPath) reuses a single TCP session for multiple commands, reducing handshake overhead. ProxyJump provides secure hop chaining without exposing private keys, unlike ForwardAgent, which poses security risks. SSH certificates, signed by a CA, eliminate the need to distribute individual public keys and support expirations and revocation. These capabilities have been stable for decades across all OpenSSH installations, yet most developers use less than 10 % of them.

Getting old Java phones online again

84 points • by waximabbax • 20 comments
Summary

The Sony Ericsson S500i can no longer use 2G data, but it still supports the Bluetooth Personal Area Networking User (PANU) profile. By configuring a Linux device (e.g., a Raspberry Pi 5) as a Bluetooth Network Access Point (NAP) you can route the phone’s traffic through the computer’s Internet connection.

Key steps: install BlueZ and NetworkManager, enable the Bluetooth service, and create a shared‑IPv4 Bluetooth NAP profile with nmcli (type bluetooth, bluetooth.type nap, ipv4.method shared). Activate the profile and verify the NAP UUID (00001116‑0000‑1000‑8000‑00805f9b34fb). Pair the phone using bluetoothctl (power on, set agent, make pairable/discoverable, pair, trust). On the S500i, locate the “Network access” service under Connectivity → Bluetooth → My devices, then create an Internet profile using the Bluetooth connection.

Test with a web request; the Pi should show a bnep0 interface in bridgelinkshow. Browsing works via the built‑in browser, Opera Mini 4.5 (proxy‑based HTTPS), FrogFind, or ProtoWeb proxies. The method requires only Bluetooth, no extra radio hardware, and applies to any Java phone that implements PANU.
