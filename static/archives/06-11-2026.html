Blender's UI and Runtime: Much Faster Than GPUI

219 points • by ppmpreetham • 29 comments
Summary

BUI (Blender UI) is a standalone UI library that reproduces Blender’s widget drawing, interaction rules, and look using a small C core (“kit”). The kit maintains a widget tree, performs layout, handles mouse/keyboard input, and renders on CPU or optional GPU (Direct3D 11 on Windows, OpenGL 3.3 on Linux). Thin language bindings expose the kit to Python, Rust, JavaScript/React, C/C++, and Dear ImGui, allowing the same widgets and behavior across languages.

Key features: - 45 Blender‑style widgets (sliders, pie menus, color wheel, node editor, file browser) plus full Tkinter and Qt‑style APIs. - Damage‑based rendering: only changed regions redraw, idle UI uses 0 % CPU. - GPU‑accelerated path draws identical pixels to the CPU raster and supports large textures, video playback, and animated image formats. - Rust bindings provide full HTML 5 element set, modern CSS (flexbox, grid, Tailwind v4), rsx!/view! markup, and gpui‑compatible syntax. - JavaScript/React and Svelte bindings render to the native BUI surface without a browser engine. - Cross‑platform native windows on Windows (Win32), Linux (X11/Wayland via XWayland), and experimental macOS Cocoa; HiDPI support included. - Install via pip (Python), cargo (Rust), npm/bun (JS), or CMake (C/C++); pre‑built wheels and binaries are available. Performance benchmarks show 2–4× lower CPU per frame than gpui‑fast, sub‑5 ms first‑frame latency, and minimal memory overhead.

sshole

2735 points • by josemrb • 130 comments
Summary

The page traces Unix password handling from the 1980 daemon entry with a literal “” (no password) in /etc/passwd to modern /etc/shadow hashes (e.g., $6$abc$… for SHA‑512). It notes that crypt() returns NULL on failure, and many programs crashed when they compared this NULL to the stored field. Musl libc changed the behavior (≈2012) to return an unmatchable character (“”) instead of NULL, preventing crashes. Musl’s SHA‑512 implementation caps passwords at 256 bytes; longer inputs cause crypt() to fail and return “*”.

In 2016 CVE‑2016‑6210 revealed a timing side‑channel: sshd returned instantly for non‑existent users. The fix hashes the supplied password with a dummy salt to equalize timing, still rejecting the login.

Alpine Docker images omitted a root password (CVE‑2019‑5021); later releases locked root with “*”, preserving key‑based logins.

A latent bug persisted: with musl (no PAM) sshd accepted any password for accounts whose shadow entry was “*” when the password exceeded 256 bytes, a condition unnoticed until a 2026 security review.
