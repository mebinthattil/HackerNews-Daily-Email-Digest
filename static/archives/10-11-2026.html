Deployed on SageMaker ml.g5.xlarge instances (≈19 GiB memory, 640 ms latency), the model processes ~5,600 tickets/hour, costing ≈$500 per million tickets—about 44× cheaper (98% cost reduction) than Sonnet’s token‑based pricing. A three‑mode switch (BEDROCK, DUAL, DECIDER) in AWS AppConfig allowed parallel evaluation and safe rollout. Metrics revealed a 74% drop in Lambda execution time. Lessons: decision models suit high‑volume, closed‑choice tasks with stable label catalogs; key order in JSON affects probabilities; and real‑traffic dual runs provide reliable validation.

Your TV can see through walls

139 points • by Curiositry • 15 comments
Summary

A spectrogram of a local TV broadcast shows selective fading caused by interference between the direct signal and a strong reflection. Moving the receiving antenna a few centimeters alters the phase relationship, producing visible stripes whose gaps correspond to path‑length changes of one wavelength. When a person walks between the antenna and the transmitter, the motion repeatedly cancels the residual signal, creating periodic gaps in the waterfall display. Measuring the stripe spacing (~70 pixels) and the waterfall refresh rate (150 Hz) yields a temporal frequency of ≈2.1 Hz. Using the carrier frequency (≈490 MHz) and the speed‑of‑light relationship, this translates to a walking speed of about 1.3 m s⁻¹ (≈4.6 km h⁻¹). The experiment demonstrates that a simple radio receiver can detect nearby motion and estimate speed, and the principle applies to any wideband signal such as Wi‑Fi or LTE, though their spectra are less tidy.

Locating the source of a mysterious beep

Summary

Beep Locator is a Python‑based web application that coordinates multiple consumer devices (iPads, phones, laptops) as acoustic listeners via WebSockets and the browser WebAudio API. Each listener continuously records a 60‑second audio buffer and runs a JavaScript detector (seedetector.js) employing a high‑pass filter and FFT to flag potential beeps. When a candidate beep is reported, the server triggers the device with the lowest round‑trip time to emit a short chirp; all listeners then upload audio clips spanning 0.6 s before the beep to 0.8 s after the chirp. The chirp serves as a common temporal anchor, allowing cross‑device alignment and triangulation using the two‑way sensing, self‑recording, and sample‑counting techniques described in the 2007 BeepBeep paper. The UI provides rough‑mode manual placement, automatic refinement, clapping tests, timestamped markers, replay controls, and a “mystery beep” designation. An adaptive module‑hot‑swap mechanism permits code updates without reloading clients. The system localized an intermittent 3345 Hz beep to within ~40 cm, revealing an old carbon‑monoxide detector with depleted batteries.

How hard is it to check for whitespace?

41 points • by theanonymousone • 7 comments
Summary

The article examines how Guava’s CharMatcher.isWhitespace determines whitespace. Unicode defines a White_Space property covering 25 characters (e.g., SPACE U+0020, TAB U+0009, LINE FEED U+000A, NO‑BREAK SPACE U+00A0, FIGURE SPACE U+2007, THIN SPACE U+2009, HAIR SPACE U+200A, OGHAM SPACE U+1680). Runtime libraries differ: Java’s Character.isWhitespace excludes U+00A0 and two other non‑breaking spaces; Python’s str.isspace includes U+00A0 and FILE SEPARATOR U+001C (29 characters total); JavaScript’s \s recognises U+00A0, U+0085, and ZERO‑WIDTH NO‑BREAK SPACE U+FEFF but not U+0085. Unicode evolves, e.g., U+180E was removed from the whitespace set in version 6.3.

Guava implements whitespace checking via a perfect hash: it multiplies the char by a constant (1682554634), shifts right 27 bits to obtain a 0‑31 index into a 32‑character table, then compares the table entry with the input char. This yields O(1) checks without collisions for the 25 whitespace characters. The constant was derived by brute‑force search ensuring unique slots. The article highlights the variability of whitespace definitions across languages and showcases perfect hashing as an efficient solution.
