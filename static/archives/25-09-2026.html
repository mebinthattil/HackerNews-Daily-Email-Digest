CVE-2025-13032: Entering and Breaking the Avast Antivirus Sandbox Part 2

39 points • by safateam • 1 comments
Summary

CVE‑2025‑13032 is a double‑fetch flaw in Avast’s kernel driver that lets an attacker cause a paged‑pool overflow. The driver reads a user‑supplied _UNICODE_STRING twice: first to size a ExAllocatePoolWithTag allocation, then again for a memmove. By racing a second thread that flips the Length field between a safe value and a large one, the kernel allocates a small buffer but copies more data, overflowing into adjacent heap objects.

The exploit sprays IORing objects, whose RegBuffers array resides in the same pool bucket. After freeing selected RegBuffers chunks, the overflowing allocation lands next to a live RegBuffers entry, overwriting one pointer to reference a user‑controlled fake _IOP_MC_BUFFER_ENTRY. This yields an arbitrary kernel read/write primitive: IoRingReadFile writes to the address in Address field (arbitrary write) and IoRingWriteFile reads from it (arbitrary read).

Using the corrupted entry, the attacker reads the MDL created for the user buffer, extracts the Process field to leak their own EPROCESS address, and repairs the corrupted ProcessBilled field to avoid a BSOD. Finally, the token of the SYSTEM process is copied into the attacker’s EPROCESS token field, achieving full privilege escalation. The vulnerability has since been patched.

Show HN: Make cursed fonts like Times New Bastard

681 points • by MitPitt • 61 comments
Summary

Bastardica is a standard OpenType font that employs a contextual substitution (“swap”) registered for every script, which browsers activate automatically. It functions wherever OpenType shaping occurs—browsers, design tools, and print—provided ligatures are not disabled. The font adds visual richness by applying Y‑offset and scaling adjustments to align glyphs precisely. When three or more fonts are combined, their glyphs intersect at regular intervals (e.g., a 5‑glyph and a 7‑glyph stride collide every 35th glyph); the first font in the sequence takes precedence, and the stride remains unchanged. Using prime‑number strides reduces such collisions. The text also lists common sources for free fonts, including Google Fonts, UNCUT, Velvetyne, Font Squirrel, FontSpace, and DaFont.

Fearless SIMD v1.0

257 points • by verdagon • 12 comments
Summary

Fearless SIMD v1.0 releases after eight years of development, offering a Rust crate that combines autovectorization, multiversioning, portable SIMD abstractions, and direct intrinsic access without requiring unsafe code. Performance‑focused features include precise and fast variants for edge‑case‑sensitive operations, native‑vector‑size APIs, fixed‑size vectors, and upstream contributions to Rust and LLVM; developers can drop to platform intrinsics when needed with zero overhead. Safety is achieved by the kernel! macro (leveraging target‑feature v1.1) to invoke intrinsics safely and a minimal, audited transmute module for load/store operations, ensuring memory safety across the codebase. Ergonomic improvements come from the #[simd] procedural macro (part of fearless_simd_macros v0.1) that handles function multiversioning without manual #[inline] annotations, while preserving backward compatibility for non‑macro usage. The crate commits to three years of security updates and anticipates support for future Rust features (e.g., f16) and hardware extensions (SVE, RISC‑V vectors) without breaking the API. Although std::simd may eventually overlap, Fearless SIMD will remain relevant as an ecosystem complement. It is already a direct dependency of 30 crates and indirectly used by over a thousand, indicating growing adoption.
