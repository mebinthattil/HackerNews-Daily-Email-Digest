Can gzip be a language model?

80 points • by networked • 10 comments
Summary

The post demonstrates that gzip’s DEFLATE compressor can function as a non‑neural language model by exploiting the compression‑prediction equivalence: a compressor implicitly assigns probabilities p to symbols, with required bits = ‑log₂p. DEFLATE keeps a 32 KiB sliding window and encodes repeated byte sequences as cheap back‑references; thus a continuation that matches recent context yields a short compressed length. Scoring candidates uses len(gzip(context + candidate)), where lower length indicates a higher‑probability continuation. Simple greedy byte selection fails because gzip reports only integer byte lengths, causing many ties. The author therefore applies beam search: starting from a prompt, repeatedly extend each of the top‑k partial continuations with every byte that appears in the training corpus, score each extension by compressed length, prune back to the beam width, and repeat for a fixed horizon. Only the most recent tail bytes remain in the scoring window to prevent degenerate verbatim loops. The method is implemented in pure Python with the standard zlib library; source code is on GitHub.

Spymarks, Not Watermarks

395 points • by possibilistic • 29 comments
Summary

Spymarks are covert signals embedded in digital media that enable persistent, user‑level tracking without the creator’s knowledge or consent. Unlike traditional watermarks—visible marks used for authenticity or ownership—spymarks are invisible, often inserted in the frequency or time domains of images, audio, video, or text. Google’s SynthID embeds up to a 136‑bit payload (e.g., a 64‑bit database ID) in a 512×512 image; similar techniques exist for audio (e.g., Timbre, AudioSeal, WavMark) and text (statistical word‑choice patterns). These signals survive common transformations such as compression, re‑encoding, and metadata stripping, making them robust to standard file edits. Early examples include printer‑tracking dots from the 1980s. Companies claim spymarks aid AI‑generated content detection, but they also allow reconstruction of content propagation and linking of media to personal identifiers (name, IP, address, political affiliation, etc.). Open‑source tools (e.g., audiowmark) can hide 128‑bit payloads protected by AES keys. The term “spymark” emphasizes the privacy risk inherent in such hidden metadata.

Transformers Explained Visually

383 points • by aray07 • 21 comments
Summary

Transformer models use self‑attention to predict the next token in a sequence. Core components are:

  • Embedding: Input text is tokenized (≈50 k tokens for GPT‑2 small), each token mapped to a 768‑dimensional vector; positional encodings are learned and added to form the final embedding.
  • Transformer Block (12 stacked in GPT‑2 small): includes multi‑head self‑attention (12 heads) and an MLP. Queries, Keys, Values are computed by linear projections of embeddings; attention scores are scaled, masked to prevent future‑token access, softmaxed, and combined with Values. Head outputs are concatenated and linearly projected. The MLP expands dimensions from 768 to 3072, applies GELU, then reduces back to 768.
  • Output Layer: A final linear projection yields logits for each of the 50 257 vocabulary tokens; softmax converts logits to probabilities. Sampling uses temperature scaling and optional top‑k or top‑p filtering to balance determinism and diversity.

Auxiliary features—layer normalization (pre‑attention and pre‑MLP), dropout (training regularization), and residual connections (gradient flow)—stabilize training. The explainer runs a GPT‑2 small model in‑browser via ONNX Runtime, with a Svelte/D3.js UI for interactive inspection of embeddings, attention maps, and sampling parameters.
