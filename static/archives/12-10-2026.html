Type-safe HTML templating in Zig

133 points • by lukaslalinsky • 12 comments
Summary

A Zig‑based HTML templating library named zt (inspired by Go’s Templ) compiles templates to Zig code at build time, allowing direct import and full type‑checking. It satisfies four core requirements: compile‑time type safety, zero‑allocation output written straight to std.io.Writer, automatic HTML‑escaping of dynamic values (with explicit {!value} for raw HTML), and a syntax that mirrors ordinary HTML. Templates are parsed, transpiled, and generate simple writer calls; layouts use @children, and control flow (if, for, switch) is expressed in native Zig code. Example usage shows rendering HomePage with a User? argument, writing to a buffered writer, and integration with the Dusty framework via res.render(.html, pages.HomePage, .{user}). Errors such as misspelled fields become Zig compile‑time errors, with comments linking back to the original template line. The library supports reusable components, layout inheritance, and safe URL attribute handling. It is early‑stage, open to feedback via GitHub issues or Zig Discord, and the author is considering syntax tweaks (e.g., @if, @for) to resolve parsing ambiguities.

Fingerprints are the new cookies

413 points • by royfish • 45 comments
Summary

Fingerprinting is becoming the primary tracking method as third‑party cookies are phased out. Websites collect data from the initial network request (IP address, User‑Agent, Accept‑Language) and from JavaScript‑executed code that probes hardware and software characteristics: GPU/driver info via WebGL, CPU behavior, memory size, display resolution, audio rendering differences, installed fonts, timezone and locale settings, CPU core count, device memory, and language. These attributes form a high‑entropy fingerprint that can uniquely identify a user within a sample set, often without needing truly global uniqueness. The article explains entropy in terms of bits of information, showing how combined independent traits rapidly narrow the candidate pool. Mitigation options include browsers with built‑in anti‑fingerprinting (Tor, Mullvad, Brave) or adding noise (farbling) as done by Brave; extensions (e.g., JShelter) can interfere but may increase uniqueness. The page itself demonstrates fingerprinting by hashing values from OfflineAudioContext, WebGL, canvas rendering, Intl, navigator, and crypto.subtle APIs.

Postgres isn't slow, your storage is

111 points • by saisrirampur • 17 comments
Summary

The talk “Postgres Isn’t Slow. Your Storage Is.” presented a benchmark comparing PostgreSQL on AWS gp3 EBS (3 000 IOPS) versus local NVMe instance‑store. Eight identical clusters (m6id.4xlarge, 16 vCPU, 64 GiB RAM, 16 GiB shared_buffers) ran a 3.3‑billion‑row pgbench UPDATE workload (64 clients, 16 workers) for five minutes. NVMe achieved a median 16 030 TPS versus 1 734 TPS on EBS (9.24× higher) and reduced median latency from 36.9 ms to 4.0 ms. Page‑read latency dropped from ~19 ms (EBS) to 0.3 ms (NVMe); WAL fsync fell from 11 ms to 1.5 ms; lock/scheduler overhead fell from 5 ms to 0.2 ms. VACUUM on 10 GB bloat took 366 s (NVMe) vs 964 s (EBS); draining a 10 GB logical‑replication backlog took 139 s vs 238 s.

Key symptoms of storage bottlenecks include slow ingestion, high P95 read latency, autovacuum lag, lengthy checkpoints, and replication lag. The proposed production pattern uses local NVMe for speed, quorum‑based synchronous replication (ANY 1 of two standbys across AZs) for availability, and external WAL‑G backups/WAL archiving for durability and point‑in‑time recovery. Real‑world cases (Instacart, Datadog) validate this architecture.

Show HN: PS2 games statically recompiled to WebAssembly

45 points • by deadxwarrior • 10 comments
Summary

The project statically recompiles PlayStation 2 EE binaries to C++, then builds WebAssembly linked with a reimplemented PS2 OS and hardware runtime that renders via WebGPU. The EE recompiler preserves R5900 quirks (128‑bit registers, multimedia ops, branch delay slots, custom FP behavior) and emits 16 KiB code units; jumps become tail calls and thread switches unwind the host stack, avoiding per‑guest stacks. The I/O Processor (R3000) runs game‑provided IRX modules on an interpreter while its kernel and libraries are re‑implemented in C++. Vector‑unit‑1 microprograms are captured at runtime, compiled ahead‑of‑time to SIMD C++ and JIT‑translated to WebAssembly as needed. Graphics use the GS’s 4 MiB of video memory in native swizzled layout, rasterized by WebGPU compute shaders with tile‑binning, preserving PS2 texturing, palette, and blending rules; a software GS reference remains for validation. Sound is modeled by the SPU2 (48 ADPCM voices, DMA streaming) and movies by an IPU MPEG‑2 decoder. Demonstrations (Gran Turismo 4, God of War II) achieve 50‑60 fps at up to 3× native resolution on an integrated GPU. Build requires Git, CMake, Ninja, a C++20 compiler (clang preferred), Python 3, 7‑Zip, and Emscripten; the workflow (port.sh) converts a disc ISO into a self‑hosted web page, streaming the disc via HTTP Range requests and storing a virtual memory card in browser storage. WebGPU support (Chrome/Edge) and cross‑origin isolation are mandatory for full performance.

Secret of Orange Cats Revealed After 60-Year Search

6 points • by bookofjoe • 0 comments
Summary

Orange cat fur is caused by a 5 kb deletion in a non‑coding region upstream of the gene Arhgap36 on the X chromosome. The deletion leads to ~13‑fold higher Arhgap36 RNA levels in melanocytes, suppressing eumelanin‑synthesizing genes and increasing pheomelanin production, which yields orange pigmentation. Two independent studies (Stanford and Kyushu University) found the deletion in every orange cat examined (145 of 188 cats) and confirmed its X‑linked inheritance. Males, with a single X, express the mutation uniformly and are usually solid orange; females, with two X chromosomes, undergo random X‑inactivation, producing the characteristic calico or tortoiseshell mosaic when one X carries the deletion and the other does not. Rare females homozygous for the deletion are fully orange. Overexpression of Arhgap36 appears confined to pigment cells and shows no adverse health or cognitive effects. Findings were reported in Current Biology (2025).
