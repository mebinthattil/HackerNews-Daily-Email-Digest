Nvidia RTX Spark encrypted firmware slows inference speed to 35% on Linux

95 points • by novaRom • 19 comments
Summary

Linux can be installed on RTX Spark laptops (e.g., MSI Prestige N16 Flip AI Plus) and will boot a full desktop with Nvidia’s open‑kernel driver, 4K 120 Hz output, and functional audio, keyboard, and touchpad after appropriate work‑arounds. The hardware reserves 96 GB of unified memory for the GPU; this split can only be changed from Windows, and lowering it to 4 GB is required for Linux to see the remaining RAM.

When the laptop is connected to AC power, Linux locks the GPU to ≈ 780 MHz, whereas Windows runs the same GPU at ≈ 2.2 GHz. This throttling stems from a Windows‑only component (“Nvidia Platform Controllers and Framework”) that decrypts an encrypted power‑table firmware and manages CPU/GPU power sharing; Linux lacks an equivalent driver, so the GPU cannot boost. Consequently, native Linux benchmarks (GPT‑OSS‑120B, vLLM) achieve only ~14 tokens s⁻¹ versus ~65 tokens s⁻¹ on Windows/WSL.

On battery, Linux clocks rise to ~1.8 GHz and performance approaches Windows levels. WSL currently offers the most practical solution, inheriting Windows’ power management while running Linux‑first AI tools. A full fix requires Nvidia to port the platform‑controller power logic to its Linux driver.

The payload backs up the eMMC, locates /mnt/flash/settings.dat, and changes the stored GMT offset from 180 minutes to 120 minutes, correcting the car’s timezone.

The lost malloc()

57 points • by matt_d • 5 comments
Summary

The post surveys memory‑allocation code in early Unix source. In Version 4 (1973) a simple linear allocator (alloc) aligns the requested size, expands the heap with sbrk(2000) when needed, and never frees memory, allowing callers to ignore NULL. In the “dmr/malloc” implementation (Dennis Ritchie’s directory) malloc(mp,size) and mfree(mp,size,addr) operate on explicit resource maps (coremap and swapmap), which are flat arrays tracking free blocks. The routines use a first‑fit list of struct map entries and coalesce adjacent blocks, handling both main memory (32‑word units) and swap space (256‑word units).

Later releases introduced allocation macros: V6’s ALLOC(x) maps to ckalloc(sizeof(struct x)); V8 adds tryalloc (zero‑initialising on failure) and new(type) macros that wrap alloc. V8 also shifts to the conventional malloc/free interface. The article notes that these macros prefigure C++’s new operator, which Stroustrup later justified as a safer alternative to manual malloc/init patterns.
