We ported the original Doom to SQL

130 points • by Vaslo • 15 comments
Summary

The project “SQLDoom” ports the original 1993 Doom’s game logic and renderer entirely to SQL, running inside a database while a Python client handles input, timing, and bitmap display. Game state (vertices, linedefs, sidedefs, sectors, things) is loaded from the Doom WAD into relational tables in about 18 s. The game loop operates at the classic 35 Hz tick rate, implemented as a series of stored procedures (cedarscript) that update entity components via bulk UPDATE/INSERT statements; a typical tick with six monsters takes ~2 ms, while a worst‑case tick consumes ~10 ms (≈37 % of the 28.6 ms budget). Rendering is a pure SQL function: a recursive CTE pipeline (≈89 CTEs, ~1300 lines) walks the pre‑computed BSP tree, performs visibility culling, projects walls and sprites, resolves depth ordering, applies colormaps and HUD, and finally aggregates 64 k RGB rows into a 192 kB framebuffer. The renderer can produce frames up to 60 Hz on an AMD Ryzen 7 7840U. Multiplayer deathmatch with up to four players is supported, and live game state can be queried via SQL while waiting in the queue.

Infidel goes wild

141 points • by tobr • 10 comments
Summary

The post documents a critical memory‑corruption bug in Infocom’s Infidel (release 22, serial 840522 for Macintosh, also present in the original 830916). The routine DESERT‑TO‑TABLE is meant to store objects dropped in the “ENDLESS‑DESERT” into a fixed 100‑value array (DESERT‑TABLE at address 11129). ZIL generated the routine with a default argument TBL that should reference the global variable DESERT‑TABLE, but the compiler substituted the global’s index (30) instead of its address. Consequently the routine writes object IDs starting at memory location 30, overwriting unused header bytes and the abbreviations table (starting at 64). This produces garbled text, loss of the word “the,” and can crash the interpreter. A similar flaw exists in PROP‑TO‑TBL/TBL‑TO‑PROP (global 22, address 11329). The bug went unnoticed because players rarely drop more than eight objects in the endless desert. Fixes include removing the default argument and initializing TBL with <SET TBL ,DESERT‑TABLE> or passing the table address explicitly.
