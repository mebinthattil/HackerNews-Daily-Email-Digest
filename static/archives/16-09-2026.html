Apple Reference Image: A New Approach for Verified Photography

222 points • by imwally • 34 comments
Summary

Apple Reference Image is a new iPhone camera mode (iPhone 18 Pro/Pro Max) that creates a verifiable, privacy‑preserving photograph. The workflow splits into two stages:

  • Secure digital negative – The sensor boots into a protected mode, signs raw pixel data, sensor metadata, and a cryptographic timestamp (lower bound) with an on‑device ECDSA key; the Secure Enclave signs additional metadata and a timestamp upper bound from Apple’s RFC‑3161 service. All elements are stored in a DNG file.

  • Reference image development – The negative is uploaded to Private Cloud Compute (PCC), which verifies sensor and SEP signatures, validates timestamps, computes a confidence score, and processes the image (demosaicing, tone mapping, compression). PCC logs the build in an append‑only transparency log, then signs the final JPEG with a hybrid post‑quantum signature (RSA‑3072 + ML‑DSA‑87).

Key properties: semantic authenticity (pixel‑to‑viewable‑image chain is provable), resilience to OS, hardware, and quantum attacks, and anonymity—no public credential links images to a device. A revocation service can invalidate individual photos or entire sensors without exposing photographer identities.

Building a Linux GPU Driver for the M4 Mac Mini in One Month

A month‑long effort by Cody Ho and Niklas produced a fully OpenGL ES 3.0‑compliant GPU driver for Apple’s M4 Mac Mini and MacBook Neo. Using a previously built hypervisor, they reverse‑engineered the AGX firmware ABI and user‑space components without inspecting Apple binaries, relying on live hardware traces and clean‑room techniques. The kernel driver communicates with the RTKit firmware via complex shared‑memory structs; the user‑space driver includes a custom IR/shader compiler, command‑stream builder, and Metal‑based shader support. LLMs (Codex, Claude) automated capture/replay of firmware events, generated kernel code, and debugged partial‑render and compute paths. The driver runs Chrome/Firefox WebGL demos and Minecraft at >200 fps, achieving full OpenGL ES 3.0 CTS pass. Source code is public (Mesa fork, Linux kernel driver, RE documentation). Remaining targets are Vulkan 1.4, OpenGL 4.6, OpenCL 3.1, Direct3D 12 via Proton, and ray tracing, with plans to upstream the driver after the M1/M2 driver is accepted.
