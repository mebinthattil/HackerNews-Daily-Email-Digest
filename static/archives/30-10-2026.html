How Do You Take a Picture of a Black Hole?

5 points • by dverlaeckt80 • 0 comments
Summary

The episode explains how the Event Horizon Telescope (EHT) turned Earth into a ~10 km‑scale radio interferometer to image black‑hole shadows. By linking existing millimeter‑wave dishes (South Pole, Chile, Mexico, Hawai‘i, Arizona, Spain, France) with hydrogen‑maser clocks and very‑long‑baseline interferometry, the consortium achieved ≈ 20 µas resolution—enough to resolve the ~50 µas event‑horizon ring of Sagittarius A (4 × 10⁶ M☉, 27 kly away) and the similarly sized ring of M87 (6 × 10⁹ M☉, 55 Mly away). The team spent two decades developing instrumentation, securing telescope time, and overcoming weather, timing, and data‑transfer challenges. Imaging M87 succeeded first because its larger mass yields a slower, more stable emission pattern, whereas Sagittarius A varies on ~30 min timescales, complicating integration. The resulting images provide direct tests of General Relativity, confirm the presence of supermassive black holes, and open prospects for time‑resolved movies of horizon dynamics by the early 2030s.

Herdr has released native app

211 points • by cherioo • 54 comments
Summary

Herdr is a cross‑platform desktop application for managing terminal sessions and coding agents. It runs on Linux (desktop session with Vulkan driver), macOS (Apple Silicon binaries; Intel builds from source), and Windows (PowerShell installer). Installers add the executable to ~/.local/bin (Linux/macOS) or %LOCALAPPDATA%\Programs\herdr‑app (Windows) and place the app in the system menu. The core process maintains terminal lifecycles; closing the UI window leaves terminals running, while closing panes or tabs terminates their shells. Workspaces (“spaces”) contain tabs that can be split into panes; each space may be named and is tied to the first terminal’s folder. An agents sidebar aggregates agents from all spaces, showing statuses (Working, Blocked, Done, Idle). Remote machines can be added via SSH, allowing spaces to run on those hosts with state synchronized across connected screens. Layouts and “mods” (JavaScript UI extensions) are configurable; key bindings are stored in keys.json. Updates are background‑downloaded and applied on restart; telemetry is enabled by default but can be disabled. Development uses Rust 1.95.0, Zig 0.16.0, and the repository includes Just recipes for building, testing, and benchmarking.

A tiny world model running games on a Raspberry Pi Pico 2 W

214 points • by airinei • 13 comments
Summary

TinyWorldFormer runs two tiny neural networks on a Raspberry Pi Pico 2 W: a looped‑transformer world model that predicts the next frame and reward from the current frame and action, and an actor that selects actions from the generated frame. The world model uses a single transformer block applied 1–4 times with shared weights; patches of 2×2–6×6 cells are embedded with position‑specific vectors, and decoding relies on three rules (background argmax, global singleton placement, sprite stamping). Models are quantized to int8 (per‑row weight scales, per‑tensor activation scales) with QAT; matrix multiplies use RP2350 SMLAD instructions and float‑32 for embeddings and norms. Training uses 1–3 M recorded transitions per game, followed by fine‑tuning on dream‑generated data. The on‑device agent employs Stream‑AC(λ) learning without replay buffers, using two 64‑unit hidden layers (32 on the Pico). Core 1 runs the dream loop (2 transformer loops per frame), while core 0 handles USB/display. Firmware fits within the Pico’s 4 MB flash and 520 KB SRAM (e.g., Pac‑Man uses 600 KB flash, 460 KB SRAM). The same engine compiles to WebAssembly for browser execution.
