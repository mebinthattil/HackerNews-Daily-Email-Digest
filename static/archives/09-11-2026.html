KetchUp – Open-source SketchUp alternative built with Rust and WebGPU

543 points • by dcoulmbe • 47 comments
Summary

BenchUp is a free, open‑source 3D modeling application aimed at woodworking and furniture design. It runs on Windows, macOS, Linux, and in desktop browsers that support WebGPU or WebGL2, requiring a mouse and keyboard. Users create models by drawing basic shapes (lines, rectangles, circles) and applying Push/Pull to add thickness, then manipulate geometry with move, scale, offset, and orbit tools. Exact dimensions are entered via snapping, typed lengths, and measurement utilities; organization is supported through groups, reusable components, and tags. Projects autosave locally and can be downloaded as portable “.ketchup” files; there is no cloud storage or account system. BenchUp imports SketchUp (.skp) files (limited to geometry) and exports Wavefront OBJ (.obj) without materials. The codebase is written in Rust and released under the MIT license, with source and contribution guidelines available on GitHub.

Declarative Dragging

586 points • by smusamashah • 25 comments
Summary

Declarative Dragging (D2) is a model‑driven approach that lets interface authors make elements draggable by specifying which future model states should be reachable through a drag, rather than coding geometry, feedback, and animation directly. The system speculatively renders each target state, extracts the element’s position, and synthesizes a smooth drag‑and‑drop interaction. D2 is composable: basic drag behaviors can be combined and extended with modifiers for floating, snapping, and transitions. The authors implemented D2 in the Dragology library for SVG web interfaces and provide a demo gallery illustrating interactive examples such as twisted‑tree manipulation and permutation labs where multiple parallel representations stay synchronized during a drag. The concept originated from prototypes for a math‑tangibility game (2022) and collaborative sketching of tree‑rewriting interactions (2023), later refined into a research contribution presented at UIST ‘26 (Horowitz, Blinn, Heer). The paper and library aim to simplify creation of high‑quality drag interactions across educational, gaming, and creative tooling domains.

Summary

Since Nov 5 2026 Microsoft’s consumer mail services (Outlook.com, Hotmail, Live, MSN) have begun rejecting messages from domains lacking a DMARC TXT record. The rejection appears as “550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records (AS9031519)”. Unlike the prior bulk‑sender rule (≥5 000 messages/day, enforced since May 2025), this change affects low‑volume senders and is not publicly announced. Only some messages are blocked, so intermittent bounces can go unnoticed. The fix is a single DNS entry: a TXT record named _dmarc with the value v=DMARC1; p=none. This record declares DMARC usage without changing enforcement for other receivers; it only satisfies Outlook.com’s requirement. Successful DMARC still requires SPF or DKIM alignment with the From domain, so the record alone won’t help if those mechanisms are missing. The change reflects a broader industry trend toward universal DMARC adoption as a baseline for email authentication.
