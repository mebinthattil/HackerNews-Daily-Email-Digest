Whistle: Speech to Text in 16.9 MB

781 points • by gmays • 67 comments
Summary

Whistle is a 16.9 MB on‑device speech‑to‑text model that runs on CPU with no external dependencies, using the same C++ engine as Needle. It accepts 16 kHz mono audio up to 30 s, detects language (English, German, French, Spanish, Italian, Dutch, Polish) or accepts a forced language code, and outputs three items: a transcript, per‑word timestamps with probabilities, and an 80 ms‑frame speech embedding.

The front‑end converts audio to 80 log‑mel bins (25 ms window, 10 ms hop, 250‑3500 Hz) and passes 3 000 frames through a 128‑channel convolutional stem that downsamples to 375 frames (one per 80 ms). The encoder consists of eight Simple‑Attention blocks (shared with Needle) with multi‑head‑convolution (mHC) residual lanes and a Monarch Hadamard MLP; attention is non‑causal. The decoder has eight laddered Simple‑Attention blocks (width 512), 8 query heads, 2 KV heads, 3‑tap causal convolutions, and engram look‑ups, plus a gated cross‑attention to the encoder output. Decoding uses a 5‑beam search with length‑normalised log‑probability and optional keyword bias via an Aho‑Corasick automaton; the vocabulary holds 8 192 subword tokens plus seven language tokens, capped at 320 tokens per transcript.

Whistle outperforms Whisper base on LibriSpeech test‑clean/other, SPGISpeech, Earnings‑22, and the FLEURS average, while Whisper is ahead on TED‑LIUM, AMI, and MLS average. It processes a 5‑second clip in 5.9 ms to first token and scales to 36.3 ms for 30 seconds. The engine ships pre‑built binaries for 17 platforms (macOS, Linux, Android, iOS, watchOS, Windows‑ARM, RISC‑V, MIPS, WASI, etc.) and provides C API functions needle_load, needle_transcribe, needle_embed. Model weights are hosted on Hugging Face; source code is on GitHub.

MXC - a sandboxed code execution system

46 points • by nreece • 7 comments
Summary

Microsoft eXecution Container (MXC) is a cross‑platform sandbox for executing untrusted code on Windows, Linux, and macOS. It abstracts a range of containment backends—including ProcessContainer, Windows Sandbox, LXC, Bubblewrap, Seatbelt, MicroVM (Nanvix), Hyperlight, IsolationSession, and WSLC—behind a unified JSON‑based configuration and policy model. Policies can specify filesystem access (read‑only, read‑write, deny lists), network egress rules (proxy, host filtering), and UI controls (clipboard, display, GUI). MXC provides a state‑aware lifecycle (provision, start, execute, stop, deprovision) and SDKs for Rust, .NET, and Node that expose versioned APIs for one‑shot or persistent workloads. Diagnostics include access‑denied logging and an audit mode that records required permissions for policy generation. Executables (e.g., wxc‑exec.exe) accept container requests directly for testing. Build requirements are Rust 1.93, Node 24+, and platform‑specific toolchains; official builds optionally send telemetry under user consent, while local builds omit it.

Keyboard differences between Windows and Macs

163 points • by sohkamyung • 41 comments
Summary
  • Key names differ: Windows “Backspace” = Mac “Delete”; Windows “Delete” = Mac “Forward Delete”. Windows “Enter” (numpad) = Mac “Return”; Macs also have a numeric‑keypad “Enter”.
  • Modifiers: Windows uses Ctrl, Alt, Shift; Mac adds Command (⌘) and Option (⌥) plus Ctrl (less common).
  • Symbol legends: Macs display icons (⌘, ⌥, ⇧, ⌃, ↩, ⌧, ⌦, etc.); Windows mostly uses text abbreviations (Ctrl, Alt, Win, etc.).
  • Shortcut notation: Windows joins keys with “+” (Ctrl+Shift+G); Mac concatenates symbols (⌃⇧G).
  • Function keys: Windows standard to F12; Mac keyboards may extend to F19 and repurpose PC keys (Num Lock, Caps Lock, Scroll Lock).
  • Accessing extra characters: Mac uses Option (⌥) and Shift‑Option combos; Windows uses Alt+numeric‑pad codes; both have locale‑specific layouts (AltGr on Windows).
  • Text‑field editing shortcuts: macOS adopts Unix‑style Control keys (⌃A/E/F/B/N/P/L/H/D/K/T/O); Windows relies on Home/End, Shift+Delete, Ctrl+Insert, etc.
  • Common shortcut differences: Redo = ⌘⇧Z (Mac) vs Ctrl+Y (Windows); Refresh = ⌘R (Mac) vs F5 or Ctrl+R (Windows).
  • Reserved keys: Windows key and macOS Fn/Globe are OS‑reserved; many shortcut combos are unavailable to apps.
  • Navigation keys behave differently: PgUp/PgDn scroll on macOS, move cursor on Windows; Home/End scroll on macOS, move cursor on Windows.
  • Additional keys: Windows includes Insert, Print Screen, Pause/Break, Num Lock, Scroll Lock; Mac adds Contextual Menu, Clear, Help, and lacks a numeric keypad.
