Why Writing Correct Software Is Hard

25 points • by AriFordsham • 1 comments
Summary

The article explains why software correctness is inherently hard. It traces the theoretical background from Hilbert’s program—seeking consistency, completeness, and decidability—to Gödel’s incompleteness theorems and the 1936 halting theorem (proved independently by Church and Turing). The halting theorem shows no algorithm can decide for every program whether it halts; reductions give two key corollaries:

  • Reachability undecidability: no program can determine whether another program ever reaches a given state.
  • Rice’s theorem: any non‑trivial semantic property of partial functions is undecidable.

The “Busy Beaver” function f(n) (maximum steps of a halting n‑state Turing machine) and the analogous proof‑size function g(n) are proved non‑computable, demonstrating that the difficulty of proving termination grows faster than any computable function. Concrete small machines (e.g., a 1919‑state TM) have termination statements independent of ZFC, showing that even modest programs can be mathematically unresolvable. The piece argues that computation, tied to physical processes, lies outside pure mathematics, and that algorithmic complexity—formalized later by Hartmanis and Stearns—captures the practical limits of verification.

Jane Street: Socratic Tutor

281 points • by tosh • 41 comments
Summary

The Socratic‑Tutor skill guides an agent to teach a user through guided questioning rather than lecturing. Before starting, the agent confirms the user wants an interactive tutoring session; single‑question requests are answered directly. The topic is broken into 4–10 concrete subskills (or a two‑level hierarchy for broad topics), each tracked on a 0–5 proficiency scale and displayed as an ASCII progress bar. A short diagnostic of 3–5 questions assesses the user’s initial level for each subskill before any instruction begins.

During the teaching loop the agent asks one question at a time, prompting the user to predict, explain, find flaws, apply concepts, or connect ideas. Incorrect answers receive narrower probing questions; correct answers may be challenged to test robustness. Brief explanations are given only for genuinely new material, after which questioning resumes. Levels advance only after consistent, independent demonstrations, with periodic unannounced reviews that can lower levels if needed. The session concludes when all subskills reach the target level (typically 4/5, or 5/5 for full mastery), followed by a comprehensive mixed assessment. Users can issue commands such as “show progress,” “harder,” “just tell me,” “save state,” and “resume from:” to control the tutoring flow.

93% of paint splatters are valid Perl programs (2019)

Summary

The paper “93 % of Paint Splatters are Valid Perl Programs” (SIGBOVIK 2019) investigates whether random paint splatters can accidentally form syntactically valid Perl code. Using optical character recognition (OCR) on a dataset of 100 splatter images, the authors find that 93 % of the OCR outputs parse as Perl programs. The study presents seven splatters that do not parse, analyzes common syntactic properties of the valid cases, and includes a gallery linking each image to its corresponding Perl source. Supplementary material provides a single‑page overview of all splatters, a tarball of the image dataset, and a link to the full proceedings (page 174). An errata section lists additional “interesting” programs identified after submission, such as OCR strings that evaluate to 0 or specific strings in Perl. Critical RCE Vulnerability in Apache HTTP Server

233 points • by soheilpro • 29 comments
Summary

CVE‑2026‑119618 is a critical race‑condition flaw in Apache HTTP Server’s HTTP/2 module (mod_http2). The vulnerability resides in the assign_headers() function, where improper synchronization of concurrent threads can corrupt heap memory, enabling remote, unauthenticated arbitrary code execution. The issue was independently discovered by Anthropic and Google Cloud’s Vulnerability Research Team; no public exploit or confirmed abuse has been reported. It affects any deployment that enables HTTP/2 in Apache versions prior to 2.4.71, as well as standalone mod_h2 builds older than 2.0.42. Wiz data indicate that 64 % of cloud workloads run vulnerable Apache instances, and 51 % are publicly exposed, creating a potential vector for lateral movement and access to cloud metadata. Mitigation steps are: upgrade Apache to 2.4.71 or later (or mod_h2 > 2.0.42); if immediate patching is infeasible, temporarily disable HTTP/2 and enforce HTTP/1.1. Wiz Threat Center provides queries to locate vulnerable assets.

AWS emulator

Summary

AWS Emulator is a local, head‑less program that mimics AWS APIs for development and CI testing without requiring an AWS account or incurring service fees. It operates in two modes: Server mode, where the SDK or CLI is pointed to the emulator’s HTTPS endpoint (127.0.0.1:9297) via environment variables; and Embedded mode, where the emulator is added as a Rust dev‑dependency and its HTTP client is wired directly into tests, eliminating the need for an external endpoint. The repository provides a workspace with one crate per AWS service, built with a Rust toolchain, C compiler, and ≥100 GB disk space; initial builds are resource‑intensive but incremental builds are fast. Telemetry is enabled by default but can be disabled via the --telemetry off flag, EMULATOR_TELEMETRY environment variable, a config.toml setting, or Embedded API options. Issues and fidelity gaps are tracked in the issues/ directory; contributions are limited to issue reporting, as PRs are not accepted. The code is licensed under CC0‑1.0, except vendor components under Apache 2.0.

Gemini Decisions API

448 points • by iamdelirium • 31 comments
Summary

Gemini Decision 1, accessed via the Decisions API, scores options without token‑by‑token decoding, achieving median compute latency of 50–100 ms (150–250 ms end‑to‑end) for up to 16 K‑token contexts and remaining stable from 1 to 100 questions per request. Zero output tokens are billed, making it roughly five times cheaper than Gemini 3.5 Flash‑Lite on the shared benchmark suite.

Key capabilities:
- Native multimodal processing of text, images, audio, video, and PDFs in a single forward pass; resolution can be tuned per visual input to balance detail and token cost.
- Supports three decision types in one request:
• noul – yes/no probability with optional true/false criteria.
• choice – multiple‑choice selection (2–255 options) with winner and normalized probabilities.
• score – ordered rubric grading, returning a continuous weighted score and per‑level probabilities.
- Each answer includes a confidence score (0–1) for routing ambiguous cases.

The API uses the same ContentBlock format as the Interactions API, allowing combined multimodal inputs such as a call recording plus account metadata or a scanned claim PDF with damage photos.
