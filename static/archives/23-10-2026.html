Local Wikipedia: Wikipedia, but only for things a half hour walk from you

294 points • by sohkamyung • 44 comments
Summary

Local Wikipedia is a web service that presents Wikipedia articles limited to a geographic radius roughly equivalent to a half‑hour walk from the user. It draws exclusively from geocoded Wikipedia pages, filtering content based on proximity to the browser‑stored location. If fewer than 25 geocoded entries exist within the area, the service expands to the nearest 25 items, typically within about six miles. Conversely, when more than 500 entries fall within the radius, only the 500 closest articles are displayed. The user’s location data remains confined to the browser session; URLs generated for sharing do not embed any location information. The platform operates independently and holds no official affiliation with the Wikimedia Foundation or the main Wikipedia site.

Docker is weird

435 points • by psxuaw • 41 comments
Summary

Docker containers are essentially isolated Linux processes, not separate virtual machines. Their isolation relies on multiple kernel features—namespaces for view isolation, cgroups for resource limits, and various networking mechanisms—to emulate container behavior. Docker images are simple directory trees that the daemon mounts using chroot/pivot_root to form a container’s root filesystem. The container runtime (runc) is written in Go, which introduces challenges because many required syscalls must run in a single‑threaded context; Go’s lack of a true fork primitive forces runc to use a special exec of /proc/self/exe to simulate fork behavior. Docker’s daemon traditionally runs as root because many kernel APIs needed for container setup require elevated privileges, especially for networking; rootless runtimes must re‑implement networking in user space. These observations highlight Docker’s reliance on core Linux primitives and the complexities of building a container runtime.

LLMs are making formal software verification feasible at a much larger scale

338 points • by johnbender • 48 comments
Summary

The authors demonstrate that large language models (LLMs), specifically Anthropic’s Claude, can generate formal proofs for security properties of real‑world open‑source software at the assembly level. Using a pipeline that translates RISC‑V binaries and Linux process semantics into Rocq, Claude proved that 239 entry points across 123 OSS‑Fuzz libraries never crash for any input under 64 MiB, producing ~180 M lines of proof (≈600 k lines per library). During proof construction the model automatically patched discovered bugs—including out‑of‑bounds reads/writes and logic errors—that traditional fuzzing missed. Additional case studies show LLM‑generated specifications for zlib’s RFC 1950 format, binary‑level verification of x86 code, and correctness of a Rust‑implemented Python interpreter via Verus. The work highlights that proofs are reusable, token‑efficient models reduce cost, and that verification scope is limited by the fidelity of CPU/OS models and specification completeness. The authors release the trusted components and a Claude skill, encouraging broader adoption of LLM‑assisted formal verification.

Summary

Berger AI claims to be the first inference provider to publish per‑request emissions, aiming to give buyers transparent data for comparing providers. The HTML-in-Canvas API origin trial

36 points • by andrewstuart • 9 comments
Summary

The HTML‑in‑Canvas API, available as an origin trial in Chrome 148‑150, lets developers render DOM elements directly into a 2‑D canvas, WebGL, or WebGPU texture while preserving full interactivity, accessibility, and integration with browser features (text selection, form controls, find‑in‑page, screen readers, extensions, DevTools, indexing).

Key points:
- Add layoutsubtree to a <canvas> to expose nested HTML to the accessibility tree.
- For 2‑D contexts call ctx.drawElementImage(element, x, y) and apply the returned transform to element.style.transform.
- WebGL uses gl.texElementImage2D and WebGPU uses queue.copyElementImageToTexture.
- Synchronize element location by converting WebGL MVP matrices to DOM matrices with canvas.getElementTransform or element.getElementTransform.

Use cases include complex canvas‑based apps, 3D scenes, games, and WebXR experiences that need native UI, copy‑paste, and searchable text. Three.js (via THREE.HTMLTexture) and PlayCanvas (via texture API) already support the feature.

Limitations: cross‑origin iframes are blocked, and scrolling/animation updates occur on the main thread, affecting performance.

The alien space of science: Coherent but cognitively unavailable directions

39 points • by martincsweiss • 1 comments
Summary

The paper proposes a framework for generating scientifically plausible research directions that are unlikely to be proposed by existing researcher communities, termed the “alien space of science.” It decomposes scientific papers into conceptual units (“idea atoms”) and clusters them to build a vocabulary. Two models are trained: a coherence model that evaluates whether a combination of atoms forms a viable research direction, and an availability model that estimates the presence of any author community capable of pursuing it. By ranking atom combinations to maximize coherence while minimizing availability, the sampler generates novel, diverse research ideas. Experiments on 16,068 peer‑reviewed LLM papers from major ML conferences demonstrate that the method produces more varied portfolios than frontier LLM baselines, while matching or exceeding per‑idea quality in blind human, LLM, and downstream evaluations. Temporal validation using only pre‑2025 data shows that selecting <1 % of candidates recovers 2025‑year combinations at 35.9× chance, and weighting unavailability improves recovery of strictly novel combinations to 3.24× chance. The approach separates scientific plausibility from community availability, enabling AI‑driven ideation that complements human discovery.

OpenShell – A safe, private runtime for fleets of autonomous AI agents

387 points • by niemandhier • 47 comments
Summary

OpenShell is a runtime that securely executes autonomous AI agents by enforcing fine‑grained policies on file access, system calls, and network connections. Each agent runs in an isolated sandbox where the kernel mediates all resources, and credentials are injected only for approved endpoints. Policy changes are formally verified before application, flagging risky new accesses for human review. The architecture comprises a gateway, supervisor, and sandbox, with support for Linux, macOS (Apple Silicon), and Windows WSL 2, plus Docker, Podman, or host virtualization. Core features include sandbox lifecycle management, filesystem/network/process policies, credential providers, extensible middleware, and optional Kubernetes deployment via Helm with required CNI NetworkPolicy enforcement. SDKs are available for Python, Node, Go, and Rust, and a public skill set enables agents to drive the CLI and manage policies. telemetry is optional and anonymous; it can be disabled at runtime or compiled out. OpenShell is released under the Apache 2.0 license.

The foolishness of "natural language programming" (1978)

151 points • by xiaoyu2006 • 28 comments
Summary

Dijkstra argues that using natural language as a programming interface is fundamentally misguided. Early computing already moved from error‑prone machine code to higher‑level languages, which, while still formal, reduced unnoticed mistakes by generating error messages. He stresses that any interface shift reallocates work: replacing formal symbols with native language would dramatically increase the machine’s processing burden without easing the programmer’s task, because communication across the interface incurs additional effort on both sides. Historical examples from Greek mathematics, medieval algebra, and the development of symbolic notation (Vieta, Descartes, Leibniz, Boole) illustrate that formal symbols enable precise, rule‑based manipulation and prevent nonsense that natural language cannot reliably exclude. Dijkstra predicts that a purely natural‑language interface would have stalled computer science, requiring centuries to achieve a usable narrow interface. He also notes a contemporary decline in linguistic precision (“new illiteracy”), further undermining confidence in natural‑language programming. Consequently, he concludes that programming in any natural tongue would be as difficult to construct as to employ.

Summary

The authors queried twelve text‑only LLMs (including GPT‑6.1 Sol, Gemini 4 Argon, DeepSeek V4 Pro, Kimi K3, Grok 4.7, Claude Opus 5.5, among others) three times each, using the prompt “What is your most controversial take about humans? …”. Seven models repeated the same claim in every response; the remaining five produced either a variant of that claim, a dissenting view, or refused. The dominant claim—appearing in all but one model—states that humans prioritize belonging, tribal loyalty, or status over truth or principled reasoning, framing consciousness as a “PR department” that rationalizes pre‑existing instincts. Six image‑generation models were then asked to create a single‑panel caricature of their controversial view; ten of the twelve images converged on a satire of humanity as phone‑addicted consumers destroying the planet, a motif absent from the text‑model answers. The experiment involved 60 API calls costing $1.54.
