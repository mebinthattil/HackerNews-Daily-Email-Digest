A font recreated from photographs of classic Commodore 64 keycaps

29 points • by sohkamyung • 3 comments
Summary

A repository provides a reconstructed “C64 Keyboard” font derived from photographs of original Commodore 64 keycaps. The package includes TTF, OTF, and web‑font files plus a preview.html tester that lets users insert special‑key and PETSCII symbols, then copy the resulting text. Features:

  • Uppercase letters, numbers, punctuation, arrows, £ sign; selected accented characters (including Hungarian); function‑key labels (F1‑F12); classic C64 key legends.
  • All 63 PETSCII graphic front legends, mapped to their original key positions; left legends correspond to Commodore + key, right legends to Shift + key (uppercase/graphics mode). Pi appears unframed on the up‑arrow key.
  • Lowercase input renders as uppercase, preserving printed key‑cap appearance rather than the screen bitmap font.

Outlines are reconstructed from the Ultimate Commodore 64 Reference and inferred from a supplied keyboard photograph; they are not exact traces. Editable glyph outlines reside in inglyphs/, with build scripts in scripts/. The project is an independent, unofficial reconstruction, version 1.107, replaceable via the provided package.

Strands Decider 2B: a small, open-source, decision model

180 points • by gmays • 21 comments
Summary

Strands Decider 2B is an open‑source 2 billion‑parameter decision model designed for fast, low‑latency inference on local CPU/GPU hardware. It repurposes a pre‑trained Qwen 3.5‑2B language‑model torso, removes the text‑generating LM head, and adds a lightweight (~1 M param) pointer head that scores candidate answers by comparing hidden states at option positions with the answer position; the torso is fine‑tuned via a rank‑16 LoRA adapter (v19 architecture).

Performance on JevBench shows competitive accuracy and calibration (ranked 3rd of 33 models in the 2 B class, 1st of 30 excluding slightly larger models) with Brier‑score‑based confidence reliability. Median decision latency is ≈115 ms on an RTX 3090 (≈153 ms on an M3 MacBook), scaling roughly linearly with token count.

The model outputs a selected option plus a confidence score, enabling applications such as model routing, tool selection, guardrails, memory/context management, policy classification, and hybrid agent workflows that combine LLMs for complex reasoning with deciders for inexpensive, deterministic choices. Code, weights, training data, and CLI tools are released on GitHub and Hugging Face for immediate experimentation.

Nobel Prize in Chemistry 2026 to Henri B. Kagan and Kenso Soai

10 points • by sasvari • 0 comments
Summary

The Royal Swedish Academy of Sciences awarded the 2026 Nobel Prize in Chemistry jointly to Henri B. Kagan (Université Paris‑Sud, France) and Kenso Soai (Tokyo University of Science, Japan) “for the discovery of non‑linear effects and autocatalysis in asymmetric organic synthesis.” Their work resolved the long‑standing problem of biological homochirality by demonstrating how asymmetric reactions can produce a single enantiomer preferentially. Kagan’s 1986 discovery introduced a method to bias reaction outcomes toward one mirror image, while Soai’s 1995 and 2003 studies culminated in the Soai reaction, the first example of a chemically induced, self‑amplifying, enantioselective process that yields exclusively one enantiomer. These findings enable chemists to design enantioselective syntheses crucial for pharmaceuticals and other applications requiring chiral specificity. The prize includes a 12 million SEK award divided equally between the laureates. Additional resources include popular‑science and scientific background PDFs.

Decisions API is in public beta

302 points • by chiefstorm • 45 comments
Summary

The Decisions API provides fast (≈10× quicker than the Responses API) typed evaluations of text, images, or combined inputs. It returns a single‑choice answer, a probability‑weighted score, or a binary predicate with an associated probability. The only available model is gpt‑6‑luna, accessed via the POST /v1/decisions endpoint. A request includes three fields: model, input (a list of user messages containing input_text, input_image, or both), and questions (each with type, name, instructions, and optional choices). Responses contain an answers array echoing the question name and providing type‑specific fields: probability for predicates, choice + confidence for choice questions, or score + probability for scored categories. Images must be supplied as inline base64 data URLs; external URLs or file_ids are unsupported. SDK examples (Python 3.26+, JavaScript 7.30+, Go 3.73+, Ruby 0.101+, Java 4.78+) illustrate constructing the request, handling predicate refusals, and extracting probabilities. Choice questions route inputs (e.g., billing vs. technical) with confidence scores, while score questions compute weighted averages across ordered levels.

ESP32-C3 Adblock

100 points • by jayhoon • 15 comments
Summary

A Pi‑hole‑style DNS ad‑blocker runs on a $2 ESP32‑C3 without PSRAM by storing 40‑bit FNV‑1a hashes of domains in flash and binary‑searching them. ≈140 k domains occupy ~0.7 MB flash and are matched in ~10 ms using ~50 KB RAM; the 40‑bit size balances collision risk (≈1 collision at 537 k entries) against flash usage. The firmware extracts the queried domain, hashes it (including parent suffixes), and either returns 0.0.0.0 for hits or forwards to an upstream resolver for misses.

Key components: - Build with PlatformIO (latest core required); copy secrets.example.h → secrets.h, set Wi‑Fi, web, and OTA passwords. - Generate the blocklist binary via tools/build_blocklist.py from hosts files, plain lists, or AdGuard rules; unsupported rules are ignored. - Flash firmware and blocklist filesystem in one USB session; subsequent updates occur OTA via a web dashboard (blocklist upload or remote URL, firmware upload, scheduled pulls). - Wi‑Fi setup via captive portal if no credentials; device discovered as c3adblock.local. - Security: HTTP Basic Auth protects state‑changing endpoints; X‑Requested‑With header mitigates CSRF; credentials are sent base64‑encoded over plain HTTP. - Features: per‑client stats, client banning, mDNS discovery, OTA updates, captive‑portal setup. Limitations include flash‑only blocklist size (≈1.3 MB with OTA firmware slots) and no TLS support. MIT‑licensed.
