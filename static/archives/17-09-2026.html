Nvidia announces native GPU programming in Rust

659 points • by nonmaskable • 31 comments
Summary

NVIDIA announced CUDA Rust, enabling native GPU kernel development in Rust with two parallel tracks that mirror CUDA’s existing models.

SIMT track (cuda‑oxide) – a custom rustc backend routes #[kernel] functions through Rust MIR, Pliron IR, and LLVM to PTX. It requires Linux, a compute‑capability ≥ 8.0 GPU, CUDA 12+, clang, and a pinned nightly toolchain. The cargo‑oxide subcommand scaffolds, builds, and runs a vector‑addition example, using types such as DisjointSlice and macros (#[kernel], #[launch_contract]) to enforce compile‑time safety (e.g., preventing aliasing of mutable buffers).

Tile track (cutile‑rs) – operates at a higher abstraction, compiling kernels via CUDA Tile IR at first launch. It runs on stable Rust 1.89+, needs CUDA 13.3, and no nightly or custom LLVM. The #[cutile::module] macro captures kernel AST; tensors are partitioned into exclusive tiles, guaranteeing safe exclusive writes without explicit thread indexing.

Both projects are early‑stage; cuda‑oxide is alpha, cutile‑rs is published and used in external projects (e.g., HuggingFace). They aim to provide safer Rust GPU programming while supporting inter‑language interoperability.

The article outlines challenges and evolution of dynamic memory allocation, emphasizing that frequent malloc/free operations become a scalability bottleneck in multithreaded programs, especially for packet‑processing workloads. It describes the classic malloc design—pre‑allocating OS memory pools and serving smaller requests—and traces its architectural layers:

  • Frontend progression: linked‑list free space → size‑class heap buckets → process‑owner encoding → core‑local allocation buffers (CLABs) → epoch encoding → large‑block mmap → hazard pointers → arena pools (per‑CPU/core) → thread‑local allocation buffers (TLABs) → constant‑time synchronization mechanisms.

  • Arena concept (introduced ~2006 in jemalloc) isolates memory by speed tier, NUMA node, or CPU core, enabling locality‑aware allocation.

The security‑audit skill is a Cloudflare‑originated coding‑agent extension that automates multi‑phase security audits of codebases. It orchestrates isolated sub‑agents through six deterministic stages:

Validators (validate‑coverage‑ledger.cjs, validate‑findings.cjs) run after ledger updates and phase completions. Multiple audit runs are additive, improving coverage. The skill requires a tool‑using coding agent, Node.js for zero‑dependency validators, and an OS‑enforced sandbox that disables external networking and limits resources. Backups Aren't Simple

225 points • by afilipovski • 46 comments
Summary

Backups require more than simple mirroring. Key concepts covered:

  • Redundancy: Keep at least three copies of data on two different media types, with one copy off‑site (3‑2‑1 rule) to protect against hardware failure, theft, or disasters.
  • Recovery Point Objective (RPO): Define how much data loss is acceptable; critical systems may need sub‑second RPO, while small setups can tolerate 24 h.
  • Snapshot rotation: Use frequent recent snapshots (daily) and less frequent older ones (weekly, monthly) to balance storage and granularity.
  • Incremental & deduplicated backups: Store only changes between snapshots, employing hard‑links or chunk‑level deduplication (e.g., rsnapshot, Borg, Restic) to reduce storage, bandwidth, and restore time.
  • Metadata preservation: Ensure file permissions, ownership, and timestamps survive transfers, especially when using object stores like S3, which may require tarball packaging to retain metadata and control costs.
  • Database handling: Dump databases and grant proper filesystem permissions to avoid corruption from in‑memory buffers.
  • Automation & testing: Schedule backups via cron, monitor for failures, and perform full restore tests at least semi‑annually.

The article concludes that mature tools abstract these complexities, providing encrypted, chunk‑level deduplicated, GFS‑rotated, point‑in‑time backups with minimal manual effort.
